## 4. M4.5 — Formula and parameter contract

### 4.1 Exact grammar and evaluation

Whitespace is ASCII whitespace between tokens, including the visual two-row wrap. `Fx =` is an optional legacy/display preamble recognized only at the beginning; never part of a parameter name. UI may compose it as the canonical fixed prefix, outside editable source, but must not add it to stored text or strip characters from existing stored source. Existing prefixed text remains parseable without rewriting it.

```ebnf
input       = ["Fx", "="], [reference, ":="], expr, EOF ;
expr        = sum ;
sum         = product, {("+" | "-"), product} ;
product     = unary, {("*" | "/"), unary} ;
unary       = ("+" | "-"), unary | primary ;
primary     = number, [unit] | reference | "(", expr, ")" | call ;
reference   = "#", identifier ;
identifier  = (letter | "_"), {letter | digit | "_"} ;
call        = ("sin" | "cos" | "tan" | "abs"), "(", expr, ")"
            | ("min" | "max"), "(", expr, ",", expr, ")" ;
number      = (digits, [".", [digits]] | ".", digits),
              [("e" | "E"), ["+" | "-"], digits] ;
unit        = "mm" | "deg" ;
```

ASCII letters only; identifiers <=48 characters. Case-sensitive. No implicit multiplication, power operator, strings, comments, assignment inside expressions, locale decimal commas, Unicode minus/degree unit, arbitrary functions, cm/m/in/rad suffix or bare identifiers. Header assignment is allowed once at top level and returns the bound parameter's quantity. Resolve `:=` before parsing the expression; do not interpret comparison/equality operators. Formula containing only whitespace clears the formula and keeps the previous accepted quantity/identity. A numeric literal-only Formula without suffix uses the destination unit for M4.4 compatibility; in compound expressions bare numbers are Scalars, never context-promoted. Thus `10` in Depth is 10mm; `10 * 2` is scalar and fails a Length destination; write `10mm * 2`.

Canonical required expression is exactly `(#EntraxeA - 2mm ) / 5 * 3 * sin(#Angle1 - #Angle2 + 3deg)` (optional `Fx =` preamble). With EntraxeA=12mm, Angle1=30deg, Angle2=3deg, expected result=3mm within 1e-12 mm. No pre-normalizing of spacing/source.

| Operator/function | Quantity rule |
|---|---|
| Unary +/−, abs | Preserve operand kind; negatives allowed internally |
| +, −, min, max | Both operands same kind, return that kind |
| * | Scalar × any kind, either order; two dimensioned operands rejected |
| / | Any / nonzero Scalar preserves kind; same-kind Length/Length or Angle/Angle returns Scalar; other dimensions rejected |
| sin/cos/tan | Angle only, converted internally to radians; return Scalar. Reject tan when abs(cos(angle)) <=1e-12 |

Every parsed literal, unit conversion and operation result must be finite; propagate QuantityOverflow/Underflow where already applicable. Zero denominator is an error, not infinity. Preserve internal negative intermediates; enforce destination kind/nonnegative magnitude/range only after final evaluation. Do not take abs of a negative result to repair a field. Keep direction independent. Numeric R8/R7 limits and editor limits are precisely M4.4's: <=99,999,999.9 in mm/scalar; <=9,999,999.9 deg; no quantization of stored f64. Positive active depths additionally exceed the geometry tolerance. Length-zero offsets remain valid.

Bound complexity before recursive work: 256 Unicode scalar values of source (existing editor limit), 128 tokens, 64 AST nodes, nesting/unary depth <=16, <=64 references per expression, document <=1024 parameters /8192 dependency edges. Check counters with fallible arithmetic. Graph traversal iterative and deterministic; no recursive graph evaluation on untrusted depth. Work is O(nodes+edges), no loops or user-defined functions. Reject limits explicitly, retain accepted state. Store diagnostic span and error code (Syntax, UnknownName, MissingParameter, Cycle, Dimension, DivideByZero, FunctionDomain, NonFinite, Underflow, Range, TooComplex, ForwardDependency).

### 4.2 Data and APIs (new model formula.rs / parameters.rs)

These are proposed replacement interfaces, not existing symbols. Remove the legacy Expression(String)/evaluate_length authority after migrating its callers/tests; use one parser and registry. Temporary compatibility adapters must delegate to it, never keep two evaluators. Literals retain exact Quantity. A field with formula has a binding to a definition; direction is outside the definition's magnitude. Source, AST, identity and cached value are four distinct values. Do not store formatted display as source or use a name as identity.

Parse/ref resolution: allocate the destination id before resolving its definition, so `#A := #A + 1mm` reports Cycle. Bind reference tokens to ParameterIds once on accepted Formula input. Topological order uses ParameterId tie-break; duplicate edges deduplicated. Unknown names reject the edit. A removed id yields MissingParameter, never rebinding to a newly created same-spelling name. Rename checks uniqueness and changes the registry name only. Existing AST bindings and preserved source continue resolving their original ids. Unchanged Formula confirmation reuses those bindings; an actual edited reference token is resolved under current names. Spans unchanged by edits outside a reference carry their binding forward using the editor edit range; a modified token must resolve again. Display source verbatim on reopen, even if it contains an earlier spelling. No naive replace, substring rename, or silent text normalization. A new formula using an obsolete name gets UnknownName. Tests must cover reuse of the old spelling by another parameter.

ParameterDraft holds definitions created by this command, changes to existing named parameters, and all field bindings. Header `#P := expr` creates P if absent; if it exists it explicitly stages a new definition for that id and binds this field to it. A field already bound to P changing only its header name renames that id, not a new parameter; a name collision is rejected. A source without header changes that field's bound definition or creates an anonymous definition if none exists. Anonymous definitions have identities but no referenceable name until named. A literal edit clears the formula for that field only, retaining its existing id/name and replacing its definition with a typed literal. Direction-only changes retain source/id/value.

On accepted changes, reevaluate the draft registry and active consumers in DAG order. A failure leaves the registry/quantities unchanged, records the rejected sequence once, and leaves editable source available for correction. Disabled branch drafts are retained but have no active consumer edges. Only reachable definitions of active fields and named definitions explicitly staged for publication participate in final validation; an inactive anonymous invalid draft cannot block another branch. Existing committed definitions must remain valid. Named definitions referenced by active fields remain active even if their source field is hidden.

**Ownership is not a dependency edge.** For a feature F, consuming its own `ParameterValue::Bound(p)` with owner F is an intrinsic input, not a reference to F's geometric outputs. Parameter definitions owned by F may refer to other parameters owned by F in any field order if the local DAG is acyclic. They may also refer to document-owned definitions and definitions owned by features strictly before F. A reference to a different feature at or after F fails ForwardDependency. Document-owned definitions may refer only to document-owned definitions; the panel used to edit a definition never changes its owner. Thus updating an earlier feature's named parameter from a later panel still enforces the earlier owner's boundary, and cannot launder a later dependency through a standalone parameter.

Use depends-on graph edges `feature -> active input parameters`, `parameter -> referenced parameters`, and `feature -> geometry/reference producer`. Do not add `parameter -> owner feature` merely because of ownership: that would create a false cycle for every named input. Reject parameter cycles (including direct self-reference), geometric self-reference to F's outputs, cross-feature cycles and external forward dependencies before geometry. A future syntax for geometry-derived parameter values is not introduced. Geometry dependencies implied by All/ThroughAll and every typed profile/support/target still obey producer ordering.

`Document::begin_parameter_draft` makes an isolated registry/counter candidate. For InsertExtrude it checks and reserves the next FeatureId in that private candidate before allocating local parameter definitions, records the captured insertion anchor, and marks those definitions `ParameterOwner::Feature(reserved_id)`. No committed feature, entity, counter, revision or notification changes. The first real `prepare_edit` must reproduce that same reservation against the same accepted source snapshot and insert F using that id; never independently allocate another owner at finalization. EditExtrude uses the existing FeatureId and existing binding ids. Document owner allocates no feature. Parameter ids likewise remain candidate-local until acceptance, with checked capacity. Multiple previews reuse this draft reservation; they do not consume committed ids.

The app binds the reservation to the command's source DocumentVersion and parameter epoch. If either changes before acceptance, reject the stale preparation/reservation; keep the user's draft available as rejected input, require a fresh command session/reservation before publication, and invalidate old certificates. Do not silently attach provisional definitions to a different committed feature that reused the raw number. Cancel or command teardown discards the private reservation. A failed preparation discards its job candidate, but retains the command reservation and editable draft for a new explicit attempt while its source version is still current; stale-source failure requires the fresh session specified above. Own-feature input/DAG exceptions are enforced by model validation, not inferred in the app adapter.

### 6.1 Geometry tolerances and termination

Canonical distances mm; angular radians. ACL uses kernel defaults linear=1e-7mm, angular=1e-12rad, relative=1e-10. Compare coordinates using `eps=max(1e-7,1e-10*S)` with S the maximum absolute coordinate and span involved. Length/sweep degeneracy uses eps, not UI one-decimal precision. Meshing deflection defaults 0.05mm as current rendering, and must not determine boolean/termination correctness. Acceptance fixtures specify their own analytic tolerance below.

Reference profile plane is P, unit normal n. Default main direction d=n from the profile's supporting face/frame (§5.1); only active Blind Along overrides it, normalized and oriented as the selected axis/edge. Blind Depth Direction Reverse flips d. Main UpTo uses n; ThroughAll uses n or -n according to Invert. Hidden Blind direction/Along/Invert never leak across branches.

UpTo target classes: exactly one **bounded planar face** or a real datum plane. Never interpret a whole Body, bbox plane or triangle index as target. Resolve target supporting plane and its trim through kernel. For each profile point p, intersection with plane q,m along direction d has signed station `t(p)=dot(m,q-p)/dot(m,d)`. Require nonparallel denominator and t(p)>eps from the displaced start across the complete section. For finite target faces, every projected ray hit over the entire swept region must lie in target trim; for Surface check the swept chain. Test edges/interior/holes analytically or by exact region predicates; vertex/centroid sampling is insufficient for holes and concave trims. No-hit/partially covered/backward/coplanar/parallel target rejects without mutation. Targets and Along are chosen from the same modal candidate-list path as profiles; no viewport subshape query is routed while that modal is open. One selected plane gives one station per ray; any upstream face resolution ambiguity rejects as AmbiguousTarget rather than choosing a triangle hit. Several eligible faces are distinct labelled candidate rows; the applied typed reference names exactly the row chosen. There is no implicit nearest-face/body-to-face resolution. Curved termination targets are outside D5's declared classes and must not be offered as candidates.

A tilted target produces a tilted end: clipping/trim of the actual extrusion against the plane, not constant depth from the nearest/centroid point. Build a sufficiently long exact prism/sheet covering the analytically bounded t(p), clip with an exact plane half-space, preserve holes and validate. Do not use split.rs's polygon path for curved edges without proof of exactness. For polygonal profile/plane intersection all station extrema occur at boundary vertices; for exact curves use exact/support extrema or a conservative certified bound inside the kernel. This is an I0 feasibility fixture too.

ThroughAll examines **all active Body/Surface geometry immediately before insertion**, independent of visibility and explicit merge scope; excludes construction, future outputs and uncommitted preview. Determine which entities the full swept section actually intersects in the positive direction, then terminate beyond the furthest such intersection. Bounding boxes may supply a conservative sweep upper bound, never the final intersection result or model shape. Use margin `max(10*eps, 1e-6mm)` beyond the furthest hit, consistent across preview/OK. No eligible geometry in the forward swept region -> NoThroughAllHit. A profile owner behind/at the start is not a positive hit; its geometry ahead may count. Multiple separated bodies all count. Extent result remains finite; overflow/unrepresentable mesh is an explicit failure. All actual reference entities and the implicit ThroughAll dependency set must pass insertion validation.

### 6.2 Composition/order table

Represent endpoints as station functions over the original profile section; oblique targets need not have a uniform station. In the following, d is the active main direction after the orientation step. A signed distance is magnitude × independent direction sign. Use the same kernel endpoint resolver for all modes.

| Order | Condition | Exact effect |
|---|---|---|
| 1 | Any | Resolve profile frame/curves, active typed dependencies and d as §6.1 |
| 2 | Main Blind/ThroughAll Start disabled | Center/start section C=P |
| 2 | Start Blind | C=P + signed(StartDistance)*d; positive shifts along d, negative opposite; independent of Depth direction toggle storage |
| 2 | Start UpTo | C is the ray-to-target section using d; each p moves to its first valid target station. Require a translated planar section (target parallel to P) for a start; a tilted start is rejected as InvalidStartPlane, not silently flattened |
| 2 | Main UpTo | C=P; hidden Start drafts do nothing |
| 3 | Main Blind | nominal primary endpoint C+D*d; D positive; Along applies before start displacements |
| 3 | Main UpTo | endpoint is exact per-ray target section; optional clearance c retracts by c*d. Require positive reach everywhere after clearance |
| 3 | Main ThroughAll | endpoint is furthest actual hit station + margin; Invert already affected d before start/hit search |
| 4 | Blind main End Offset disabled | endpoint unchanged |
| 4 | Blind main End Offset Blind | add signed(EndDistance)*d to nominal endpoint; require endpoint ahead of C everywhere |
| 4 | Blind main End Offset UpTo | replace nominal endpoint with ray-to-target section from C, not “add distance to another target” |
| 5 | Sides One | sweep section between C and final primary endpoint |
| 5 | Sides Symmetric | reflect final primary endpoint about C (station negation), sweep both sides. Depth D is per side, total 2D. Start shifts C once; primary end adjustment is reflected. Main UpTo/ThroughAll determines primary side then reflection, not a second target search |
| 5 | Sides Second Blind | independent reach from C along second reference -d; Forward uses -d, Reverse uses +d. Main direction toggle never rewrites the second magnitude/direction. Union both swept regions; overlap counted once |
| 5 | Sides Second UpTo | solve that target from C along -d. Optional unsigned nested Blind EndOffset retracts toward C; nested UpTo replaces this endpoint using its own target along -d |
| 6 | Any | Build union of side regions once, perform result mode against targets, validate all components, then tessellate |

For reversed Second Blind on the primary side, the geometric span is the union of both intervals from C, not their sum; valid if the final union has positive extent. Reject collapsed, reversed primary reaches, self-overlapping sheet sweeps and nonmanifold unions. Symmetric suppresses all second-side inputs and nested offsets. “Second end position” and “2nd side” are the same state; labels/indentation remain canonical. No ThroughAll second-side mode is introduced. Offsets can be zero; enabled UpTo offsets require a target. The currently bare main UpTo Offset needs D3; do not activate hidden EndDistance as its value.

## 8. M4.10 — Worker, command machine and atomic publication

### 8.1 Minimal worker arrangement

One dedicated std::thread for all Newell geometry jobs; std mpsc for messages; event-loop user event wakes completion handling. No thread pool/job framework and no polling loop. Keep existing DocumentSession on UI/controller thread; it remains the authoritative accepted parametric Document. Kernel topology and immutable generation cache live on worker in newell-kernel. Worker is constructed inside its thread closure. It receives owned model Document clones/recipe DTOs and allocates topology locally; it never receives or returns NewellSolid, Topology, FaceId, Arc<topology> or a mutex guard.

```rust
// app::geometry_worker; these are proposed types
pub struct GeometryJobId {
    document: DocumentInstanceId, session: CommandInputSessionId,
    base_revision: u64, draft_revision: u64, serial: u64,
}
pub struct PrepareGeometry {
    id: GeometryJobId, base: Document, edit: DocumentEdit,
    insertion: Option<FeatureId>, parameter_edits: ParameterDraft,
}
pub struct PreparedGeometry {
    id: GeometryJobId, prepared: PreparedDocument, token: NewellGeometryToken,
    scene: SceneSnapshot,
}
pub enum GeometryFailure { Model(ModelError), Kernel(NewellKernelError),
    Transport(String) } // owned, Send DTOs; no winit/UI/GPU error payloads
pub enum WorkerReply { Ready(PreparedGeometry), Failed { id: GeometryJobId, error: GeometryFailure } }
```

DocumentEdit has exactly the three variants defined in §7, including the validation-only references for both Extrude variants; no generic command framework. The worker calls model candidate validation, kernel replay, then model candidate finalization using kernel manifests. Candidate ids are reserved/allocated only on the private Document clone; local parameter ownership uses the same feature reservation established by §4.2. `CommitManifest` is model-owned and records insertion/replace identity, effective dependencies, the exact `ExtrudeValidationRefs` snapshot (empty for ParameterDefinitions), parameter epoch, reserved feature identity, output mapping and resulting generation. The outer GeometryJobId records the app source revision. The worker seals this manifest with the candidate inside PreparedDocument; there is no independently mutable duplicate manifest in WorkerReply. Stage shape generation on worker before sending Ready, with an opaque token scoped to worker epoch and document; the finalized document inside PreparedDocument holds that generation number. Tokens are integers with checked allocation, not topology pointers. The worker retains staged immutable shapes until accept/release. App-to-worker control messages are Prepare, Cancel(session), RetainCommitted(token), Release(token) and ReplaceDocument(instance); they carry no native geometry. It can reconstruct from accepted recipes if a cache is lost; cache is not the parametric source of truth.

Concrete model transaction APIs in `model/geometry.rs` and `app/document.rs`:

```rust
Document::prepare_edit(&self, edit: &DocumentEdit, parameters: &ParameterDraft,
    insertion: Option<FeatureId>) -> Result<DocumentCandidate, ModelError>;
DocumentCandidate::finalize(self, result: GeometryResultManifest)
    -> Result<PreparedDocument, ModelError>;
PreparedDocument::manifest(&self) -> &CommitManifest;
Document::validate_prepared(&self, prepared: &PreparedDocument) -> Result<(), ModelError>;
DocumentSession::accept_prepared(&mut self, expected: DocumentVersion,
    prepared: PreparedDocument, token: NewellGeometryToken)
    -> Result<CommitReceipt, AppError>;
```

`DocumentEdit`, `DocumentCandidate`, `PreparedDocument`, `GeometryResultManifest` and `CommitReceipt` are model-owned and contain only recipes, quantities, dependency/output mappings and ids. `DocumentVersion { instance, revision }` and the token association belong to app's DocumentSession. `GeometryResultManifest` converts the kernel manifest through the worker adapter; no kernel type enters model signatures. `PreparedDocument` fields and constructors are private to the model finalization path; finalize validates result kind/counts/dependencies, frozen request/validation payload, output generations, reserved owner identity and all id capacities. WorkerReply carries this finalized type, never an unfinalized Document. `Document::validate_prepared` repeats boundary, retained-reference and source-identity preflight against the still-accepted Document without doing geometry or accepting a plain Document. The consuming document extraction is used only after successful app acceptance preflight; no Extrude metadata-only commit API remains public. The app wraps it with the matching job/token; acceptance rejects any mismatched token/manifest. `CommitReceipt` records feature (optional for parameter-only edits), revision, active outputs and retired outputs. Existing metadata-only Extrude commit methods must become internal candidate helpers or require this prepared authority; update callers rather than keeping an accessible bypass.

No Send/Sync assumptions are needed for topology. Compile-time assert Send for actual message DTOs, including PreparedDocument with owned maps/strings/quantities and NewellMesh's Vec buffers. Do not add unsafe impls or serialize topology to evade ownership. The inspected Clone topology permits local scratch generations but does not itself prove any cross-thread trait.

One running compute and one newest waiting preview per session. Coalesce by replacing waiting previews; don't enqueue one per keypress. A queued OK preparation supersedes that session's preview and retains its explicit attempt. Cancel/session change increments local lifetime and marks its atomic cancellation flag; check between replayed features, boolean operands and meshing stages. Cannot forcibly interrupt a BrepKIT call; let it finish, ignore stale result, release token. UI never joins/waits for a running geometry call, including Cancel and document replacement. Shutdown drops channel and lets the worker exit after the active call; no GUI-blocking join. Bound waiting jobs and prepared tokens: keep current committed generation, one accepted preview, one in-flight plus one newest waiting; release superseded generations, never evict a token referenced by an accepted Document.

Reply eligibility checks **all** job fields, current document revision, parameter epoch, captured insertion anchor, current latest requested serial and geometry source generation. A failure from a stale job is also ignored. Palette/theme/scroll/layout changes do not invalidate a geometry job but do invalidate inappropriate UI certificates. Draft revision increments only on accepted semantic edits/branch/selection changes; source text still being edited is not geometry input. During an incomplete/invalid field edit clear stale preview, keep accepted numeric draft, and mark current command nonconfirmable until resolved. Do not display the last successful preview as though it were the newly requested operation.

### 8.2 States and transition table

The app owns command lifecycle; model CommandController keeps semantic draft only, not GPU resources. Keep M4.4 attempt/delivery structures and adapt them instead of adding another competing confirmation latch.

| State | Ownership and admitted actions | Transition |
|---|---|---|
| Idle | Only accepted Document/generation/scene; no drafts | Explicit Extrude open -> Editing |
| Editing {session,draft_revision} | Accepted numeric/selection/parameter drafts; optional current prepared preview; committed scene retained separately | Accepted edit -> enqueue/coalesce ComputingPreview; OK -> consume attempt and drain sequence barrier |
| ComputingPreview | Worker scratch topology; no persistent mutation; UI accepts new edits, Cancel, selection and mode changes | Matching Ready -> ReadyPreview; matching error -> Invalid; superseded reply -> release |
| ReadyPreview | Immutable exact operation result and candidate manifests for this job | Edit invalidates; OK validates exact prepared key then accepts, or queues final preparation if needed |
| Invalid | Accepted field draft plus actionable validation/geometry error; committed scene displayed, no stale preview | Correcting edit -> compute; explicit OK can retry only after current barrier/validation; stale source/reservation requires a fresh command session (§4.2); Cancel allowed |
| PreparingConfirm {attempt,job} | Attempt consumed once; fields frozen for that attempt; current accepted Document unchanged | Matching Ready + final preflight -> commit; failure -> stored rejected ack; Cancel before model acceptance invalidates pending attempt and releases eventual result |
| CommittedAwaitingDelivery | Model candidate accepted exactly once; feature/result/generation recorded; pending successful terminal outcome | Only publication retries; no edit/Cancel/Formula/operation switch for old session. Document replacement/close may tear down old UI lifetime without reverting commit |
| RejectedAwaitingDelivery | Attempt result stored, drafts retained | Retry acknowledgement only; on successful delivery -> Editing/Invalid; new explicit OK gets a new attempt |
| Closed | Acknowledged success or Cancel; release drafts, modal sessions and preview tokens | New activation creates a fresh command session/defaults |

While PreparingConfirm, command switching cancels the uncommitted attempt/session then opens the new command; while CommittedAwaitingDelivery it first resolves the stored outcome as M4.4 requires. Document replacement invalidates every old job/picker/formula/terminal delivery namespace immediately, clears old scene/picking, then prepares/displays the new accepted document. Reused raw entity/session numbers cannot accept old replies. Worker failure/channel closure leaves last committed scene and an explicit unavailable error; reject pending OK, no history mutation. A new explicit retry may restart worker and rebuild accepted recipes; no permanent background retry loop.

### 8.3 Commit protocol and rendering

1. At OK drain all numeric/Formula/selection requests through the attempt barrier using current certificates. Check no rejected/incomplete active edit. Consume NumericConfirmAttemptId before any fallible preparation. Do not close any owning panel or discard drafts.
2. Freeze exact active spec/parameter edits/boundary, prepare geometry asynchronously. Reuse an already ReadyPreview only if full job/source/revision identity matches; no new geometry on the UI thread.
3. On matching Ready, main-thread `DocumentSession::accept_prepared(expected: DocumentVersion, prepared: PreparedDocument, token: NewellGeometryToken)` rechecks namespace/revision/counter capacity, boundary/dependencies and token/manifest identity. Call model `validate_prepared(&prepared)` against the accepted document, including its sealed retained-reference payload and local-owner exceptions. No geometry call here. Swap the fully validated document extracted from PreparedDocument and accepted geometry-generation token as one nonfallible state replacement after preflight. The worker's token already retains all topology; accepting it does not require a second fallible worker operation. Send advisory RetainCommitted/ReleaseOld for lifetime management after acceptance. Failed messages cannot erase geometry already retained by a live accepted token.
4. Record committed attempt/session/feature and publication obligation before attempting UI/render upload. Publish exactly one Changed notification. A retry never reruns candidate preparation, id allocation, parameter edit, model swap or feature confirmation. Replace existing metadata-only confirm_before authority with this prepared commit path; keep its preflight/candidate-swap semantics. There must be no public app route that commits Extrude metadata without prepared geometry.
5. Publish tree, selection and scene as a coherent document/generation snapshot. Preserve ProjectionSync/NumericDelivery obligations; one +100ms automatic retry, then suspend until existing user/layout rearm. Failed scene GPU upload retains the obligation and marks that scene generation unavailable for picking; never show old geometry under new ids. UI may retain its prior complete snapshot pending publication. Successful terminal acknowledgement only after a complete required view publication; model commit remains successful if delivery is delayed.
6. Cancel before acceptance invalidates work and clears preview; republish latest committed scene/selection, not a hard-coded box/depth. It does not restore a snapshot over someone else's accepted document mutation. After successful acceptance Cancel cannot roll back that commit; terminal delivery rules apply.

`SceneSnapshot` contains document/generation and ordered `SceneItem { binding, mesh, selected }`; binding is `Committed(EntityId, GeometryGeneration)` or `Preview(session,draft_revision,output_key)`. Maintain face/edge binding tables per item; merge meshes only with explicit triangle/range-to-item and face-key mapping. Renderer uses item selected boolean once; previews have no global EntityId and are excluded from persistent selection and target candidates. CPU picking maps hit -> current item binding -> face key under the same mesh/generation certificate. Do not bind preview to Base Solid. Navigation sees bounds of the composed scene and mesh changes cancel capture without reframing, per existing rules.

Preview scene is the complete hypothetical final scene: unchanged committed items plus candidate replacement items, with consumed targets omitted. Preview Add must show the union, Remove the cut result, not just the tool volume. Cancellation needs no inverse boolean because accepted scene is retained. No new preview colour/transparency/animation is authorized. Surface preview uses actual uncapped faces and correct feature edges. Final committed scene and current matching preview must have identical geometry/measures, apart from preview versus committed bindings and selection brightness.
