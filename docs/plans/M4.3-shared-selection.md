## 3. Ownership, identities and ordered set operations

### 3.1 Model and app contracts

Keep Selection in newell-model, outside Document. Add these methods; existing
replace/toggle remain source compatible. Equality before/after determines change.

```rust
impl Selection {
    pub fn add(&mut self, entities: impl IntoIterator<Item = EntityId>);
    pub fn remove(&mut self, entities: impl IntoIterator<Item = EntityId>);
    pub fn clear(&mut self);
}
```

App's new private `selection.rs` module defines these concrete contracts. These
are Controller data, not new persistent entities or a new multi-window manager.

```rust
pub(crate) enum SelectionOp { Replace, Add, Toggle, Remove, Clear }
pub(crate) struct WindowSelection {
    document: DocumentInstanceId,
    value: Selection,
}
pub(crate) struct SelectionRequest {
    document: DocumentInstanceId,
    op: SelectionOp,
    entities: Vec<EntityId>,
}
impl WindowSelection {
    pub(crate) fn new(document: DocumentInstanceId) -> Self;
    pub(crate) fn entities(&self) -> &[EntityId];
    pub(crate) fn apply(&mut self, request: SelectionRequest,
        session: &DocumentSession) -> bool;
    pub(crate) fn reconcile(&mut self, session: &DocumentSession) -> bool;
}
pub(crate) fn resolve_tree_selection(session: &DocumentSession,
    target: TreeTarget) -> Option<Vec<EntityId>>;
```

`None` means invalid, stale or structural target: no selection change. `Some([])`
means a real operation with zero outputs: Replace clears; other operations no-op.
`apply` refuses a mismatched namespace, verifies every id exists before changing
anything and refuses the entire invalid request. Reconciliation is the separate
pruning path. Never reinterpret stale numeric ids in a replacement document.

| Operation on S with input I | Result |
|---|---|
| Replace | First occurrence of each id in I, in input order |
| Add | S followed by first occurrences of ids in I absent from S |
| Toggle | Deduplicate I first; visit once in input order, removing members and appending nonmembers |
| Remove | Remove all members of I, retaining survivor order |
| Clear | Empty |
| Same resulting vector | No notification, no recomposition requested solely for selection |

Deterministic order is user insertion order, never BTreeMap/set sort order. A
tree operation's input is exactly Feature::outputs() order; a candidate list uses
document feature order then output ordinal before any filtering. Same names remain
distinct. Re-add after removal appends. Reconciliation removes missing ids without
sorting survivors. Id verification is app-side; the model Selection utility does
not know a document. Vec-based membership is sufficient for this milestone; O(1)
is required for UI routing, not selected-set updates or CPU triangle queries.

## 4. Input decisions and actual viewport granularity

### 4.1 Decision table

Modifiers for entity-selection activation: none = Replace; Shift = Add; Control
or macOS Super = Toggle; toggle wins if combined with Shift. Alt does not add a
selection operation or prevent the existing camera gesture. No range selection.
These are proposed M4.3 interactions, not claims that current tree routing supports
modifiers. Add/remove/clear also exist as app operations for tests/panel commits.
Tree keyboard requests receive the same current modifier snapshot as pointer input.

| Source / target | Entity request | Other retained behavior |
|---|---|---|
| Viewport primary click, bound mesh hit | Modifier operation with the single bound entity | Only on valid release below threshold |
| Viewport primary click, geometric miss | None: Clear; additive/toggle: unchanged | Only exposed scene pixels |
| Viewport hit on unbound preview or stale binding | No request, including no miss-clear | Navigation remains available |
| Elements name or row padding | Modifier operation with that entity, even hidden | Focus that semantic row; second name press may Rename |
| Features operation name or row padding | Modifier operation with all ordered output ids, zero/one/many | Focus operation; second name press may Rename |
| Folder/group/root name or row padding | No entity request | Focus only |
| Tree `[-]`/`[+]` handle | No entity request | Expand/collapse, focus retained |
| Elements `□`/`■` | No entity request | Existing persistent visibility edit; independent of membership |
| Playhead, dividers, tree blank space | No entity request | Existing cursor/drag behavior |
| Tab/BackTab or keyboard movement | No entity request | Move semantic focus only |
| Enter/Space on focused leaf entity/operation row | Same request as row click | Existing keyboard activation path, exactly once |
| Enter/Space on expandable focused structural row | No entity request | Preserve expand/collapse behavior |
| Enter/Space on focused checkbox/marker | No entity request | Its own action |
| Primary drag, secondary/middle press/drag, wheel/pinch, Home | No entity request | Preserve camera semantics and ownership |
| Overlay/menu-covered target or stale TreeHitToken | No entity request | Existing precedence/dismissal; no click-through |

Do not toggle twice on a name double-click. First press selects; second recognized
Rename press only opens Rename. The existing 500 ms semantic double-click behavior
and full-name editing survive; Cancel does not undo the first selection.

Extend TreeIntentKind with `Select { edit: SelectionEdit }`. Payload is the semantic
target, already carried by TreeIntent. App resolves outputs, checks generation,
document and current membership/existence. Structural rows do not emit Select.
ShellController's pointer/key entry points use a stored model-free modifier value
set by `set_selection_modifiers(shift: bool, toggle: bool)`; App adapts winit modifiers.
Keep existing pointer/key signatures and public test helpers source-compatible.
Both keyboard routes (`activate_tree_hit` and base_key) must use the same helper;
remove the unconditional keyboard `selected` assignment.

### 4.2 Click release certificate

Retain navigation's existing strict threshold: distance squared greater than
`4.0 logical px` squared captures drag; equality remains a pending click. Do not
invent a second threshold in app. Add:

```rust
// navigation.rs: called before release clears pending_drag
pub fn finish_primary(&mut self, point: (f64, f64)) -> Option<(f64, f64)>;
```

It checks the final release displacement too (a final motion event is not
guaranteed), returns the original press point only for a still-pending primary
press within threshold, and always releases that primary press. Active orbit,
canceled/invalid/nonfinite input or another button yields None. It never changes
the camera on release. Leave secondary/middle release behavior intact.

App retains `PendingSceneClick { document, generation, mesh_revision, edit }` only
after the same admitted primary begin. Record modifiers at press. On release,
first obtain the certificate, verify document, layout/routing generation and mesh
revision still match, and verify release remains exposed. Pick at the certified
press point, not a shifted release target. Distinguish a true ray miss from an
unbound hit. Then issue at most one request. Clear pending state on threshold
capture, focus loss, pointer exit, overlay/menu opening, resize/scale, projection,
layout/occlusion, mesh replacement, document replacement and keyboard/navigation
interruption. Returning near the press point after a drag never re-arms a click.
Other buttons' releases cannot commit or terminate the primary session.

App allocates checked monotonically increasing ids; never wraps/reuses a live id.

| Transition | Applied/authoritative result | Draft and focus |
|---|---|---|
| Open Window | Snapshot of current ordered window selection | Draft clone, offset zero, first item or OK if empty |
| Open Field | Snapshot of that command input, not a universal panel applied array | Draft clone; remember exact operation/key and session |
| Candidate checkbox activation | No committed change | Toggle id once; preserve survivors; newly checked appended; max=1 replaces draft with the activated id or clears it |

| Cancel / Escape | Neither destination changes | Discard draft and close; Escape is consumed before command Cancel/fullscreen handling |
| Outside press | No committed change | Existing modal blocking/dismissal policy; no underlying activation |
| Missing originating field/command switched or closed | Neither destination changes | Cancel, drop pending completion; safe ordinary focus fallback |
| Replacement namespace | Window clears; command inputs reset | Cancel all sessions and captures before publishing new namespace |

SelectionPanel no longer owns a long-lived applied selection. Its initial applied
snapshot exists only to support the current transaction. `status` is presentation
state, not an instruction to commit repeatedly. App validates session id, namespace,
destination and current candidates/cardinality, then consumes completion regardless
of validity. A replay or completion from a closed/replaced command does nothing.

### 5.2 Candidate policy and command input ownership

App `CommandSelectionInputs` stores a map from SelectionFieldKey to Selection plus
the command session/document, and its opening snapshot. It is a command draft,
separate from WindowSelection and Document. Start a new session at an actual Action
Box restart/operation activation, including restart of the same operation; do not
detect a session solely by operation equality. Add a consumed shell command-start
signal to the existing action route. No selection panel is allowed without a live
matching command session.

At command start, seed only documented entity inputs from filtered window
selection; seed Body merge scope from selected Bodies. Other inputs start empty.
Subsequent window selections do not overwrite these snapshots. Opening a field
does not reseed it. Field candidates edit only that field's command input.

Candidates always include hidden eligible entities; visibility is unrelated.
Build rows from document feature/output order and full names; no search widget,
spatial eligibility or inferred topology. Filter against the captured insertion
boundary for current Extrude references: only outputs whose producer precedes the
captured Before feature; End admits all existing outputs. Revalidate on OK and
before command confirmation with M4.2 preflight.

| Role | M4.3 candidate rule / cardinality |
|---|---|
| Window | All existing entity kinds / unbounded |
| MergeScope, Bodies (e.g. Boolean Tools) | Body / many |
| BodyTarget (Boolean Target) | Body / max 1 |
| SurfaceTarget (Up to/offset target) | Surface or Construction(Plane) / max 1 |
| Axis | Construction(Axis) / max 1 |
| Direction | Construction(Axis) / max 1 |
| Path | Construction(Curve) / max 1; reference metadata only, no path geometry evaluation |
| UnsupportedTopology (e.g. Boolean Faces) | Empty: no supported stable face entity kind today |
| EntityReference (e.g. Loft Match/Connection input) | All existing kinds / max 1; UI reference only, no geometry contract |

Map descriptors in each ActionBoxUi implementation using its named constants,
not numeric label searches: MergeScope for K_MERGE_TARGETS; Extrude Along=Direction
and target fields=SurfaceTarget; Revolve Axis=Axis and target fields=SurfaceTarget;
Sweep Path=Path; other existing entity inputs use their documented role; Boolean
Target=BodyTarget, Tools=Bodies, Faces=UnsupportedTopology. Distinguish
ActionOperation as part of every field key where numeric control ids overlap. All
select_keys must have one descriptor.
Empty candidate lists compose §21's inert empty content row and OK/Cancel; no mock
fallback, new error marker or claim that unsupported topology was selected.

Add to ActionBoxUi:

```rust
fn selection_descriptor(&self, key: u32) -> Option<SelectionFieldDescriptor>;
fn set_selection_counts(&mut self, counts: &BTreeMap<u32, usize>);
```

Use an optional runtime count map on each box outside its Copy mock values.
In application mode every selection row reads this map, including merge helper
rows; absent key means zero. Explicit reference fixtures continue to use their
MockSelection values and exact existing artwork. Restart must not accidentally
switch an application box back to mocks. Supplied counts cannot activate mock
cycling. The app supplies every field's count from that command session, including
hidden fields so re-exposing them preserves their input. Field hiding cancels an
open session from that field; it does not erase the saved command input.

`sync_extrude_command` reads command entity inputs from CommandSelectionInputs,
never App.selection on every event. `merge_with_all=true` sends empty merge_scope while retaining the explicit command
scope for when unchecked. OK in a picker changes only the command draft/preview;
it cannot create a feature. Outer command OK keeps existing one-shot insertion and
preflight; outer Cancel drops command inputs and restores their opening lifecycle,
without reverting independent window selection. Other boxes get real UI input

## 6. Synchronization, publication and stale events

### 6.1 Exact event paths

1. Tree pointer/key -> O(1) grid target -> current TreeHitToken validation ->
   Select intent -> app resolves against current DocumentSession -> WindowSelection
   applies -> model-free selection view fan-out -> shell publish -> App::apply.
2. Viewport press/move/release -> navigation click certificate -> qualified hit
   binding -> WindowSelection applies -> same fan-out. No persistent notification.
3. Field activation -> validated OpenField -> app rows/applied snapshot -> panel
   opens -> draft-only editing -> certified close completion -> app destination
   replacement -> count/selection fan-out -> App::apply. Cancel emits no replacement.
4. Persistent mutation -> existing DocumentNotification -> ProjectionSync ->
   candidate document/tree/selection reconciliation -> atomic shell publication ->
   acknowledgment -> App::apply. Notification consumption is not acknowledgment.

In finish_shell_input, consume the originating tree/selection/command-start intent
before publishing derived updates that could advance generation; validate and take
once. Selection setters never emit Select/Open/Complete. Do not round-trip a
programmatic view update as user input. No loops, synthetic DocumentChanged events,
or idle polling of selection status.

### 6.2 Publication failure and lifecycle

Extend ShellController with an atomic candidate publication seam:

```rust
pub fn set_document_view(&mut self, projection: ModelTreeProjection,
    view: LocalSelectionView) -> Result<Update, UiError>;
pub fn set_selection_view(&mut self, view: LocalSelectionView)
    -> Result<Update, UiError>;
pub fn set_entity_selection(&mut self, selection: EntitySelectionView)
    -> Result<Update, UiError>;
```

Keep set_tree_projection for public/reference callers, delegating to the same
candidate path with the current selection pruned to the supplied projection.
The controller's entity-only convenience setter preserves current field counts;
the app uses combined LocalSelectionView setters for authoritative fan-out.
Add ShellState::set_selection_fields(&mut self, fields: &[SelectionFieldCount])
-> Result<bool, UiError>; it groups counts by operation and calls the named
ActionBoxUi setter without emitting input. Duplicate/unknown fields are invalid.
Use a complete field list, with zero for empty fields, to prevent stale counts.
App uses set_document_view in ProjectionSync's publication closure: build/validate
tree, selection mirror, reconciled panel and field counts on a candidate shell,
compose, publish together. A failed publication leaves the last valid frame and
generation intact; ProjectionSync retains its existing obligation/retry budget.
Do not acknowledge a tree refresh before selection reconciliation is included.

For a local selection-only publication error, keep authoritative selection but set
an app `selection_view_pending: bool`; one +100 ms automatic retry, then suspend
until explicit input/layout/new selection rearms. Reuse the same two-attempt policy
and earliest-deadline scheduling as ProjectionSync; keep a separate local retry
record because document revision may be unchanged. Clear it only after a successful
current-state publication; coalesce rapid selection changes. A successful document
publication containing the latest selection satisfies it too. Avoid continuous
redraw/retry and do not mutate a persistent revision to obtain a refresh.

Namespace mismatch with current DocumentSession immediately blocks old-tree/select/
completion delivery even when an old frame remains during failed refresh. Clear
WindowSelection, bindings, pending clicks, command input sessions and modal authority
on replacement before accepting further user requests; publish the empty selection
with the new document. Do not defer authoritative clearing until projection success.

Same-document rename, reorder, scroll, collapse or relayout preserves entity ids and
selection order. Tree focus remains its own semantic target and does not jump to
the selected entity; programmatic selection does not auto-expand or auto-scroll.
Visibility changes preserve selection and candidate membership. Entity removal prunes
selection and command inputs, and reconciles panel rows plus applied/draft survivor
order. Deleted inputs cannot be restored by Cancel. Renames refresh panel labels
without losing draft edits; newly eligible rows are unchecked. Capture is canceled
on external candidate count/order/geometry change; retain or clamp numeric offset
according to README_UI.md §21, including its focus fallback rules.

Selection completion needs a controller-owned session certificate analogous to
Rename: remember id/document/destination and bound generation; advance its bound
only through that session's own valid modal publications and harmless external
reconciliation that preserves it. Certify its own OK/Cancel close once; old WidgetIds
never authorize a later session. Unrelated remaps invalidate pending hits. Include
selection-row semantic id/part mappings in effective-route equality, not only raw
WidgetIds; same routing with new labels need not advance generation. Clearing on
replacement still invalidates the namespace even when ids/cells are reused.

Existing owned playhead/divider and selection-thumb drags must survive their own

### 7.1 Selected viewport geometry: 10% brighter

The human requests a selected model to become 10% brighter. Make that precise as
a 1.10 multiplier on the existing geometry RGB after its usual lighting, before
framebuffer encoding: `selected_rgb = min(original_rgb * 1.10, vec3(1.0))`.
Unselected output uses exactly the original RGB. This is a proposed numeric
interpretation for revision approval: it is a relative brightness increase,
not a 10-percentage-point addition or interpolation toward white. Alpha remains
unchanged. Apply once, never cumulatively, and restore original output immediately
on deselection. No animation, glow, outline or hover-dependent color is added.

Apply to all fragments belonging to the represented selected entity: lit/unlit
surfaces, wireframe, points, visible geometry lines and existing hidden-line dashes
in every current SceneDisplayMode. Preserve lighting contrast, depth, clipping,
occlusion and dash masks. Do not brighten the viewport background, UI, unbound
preview or unselected geometry. Theme and View > Color do not enable/disable this
geometry effect. The relative multiplier is the same in all four UI palette states.

The present renderer has one displayed mesh. App computes the selected boolean
only from a valid SceneEntityBinding for the current document/mesh revision whose
entity belongs to WindowSelection. Selecting an operation highlights its displayed
bound output when that id is among its resolved outputs. Entities without a
displayed mesh receive no fictitious highlight. Binding removal, replacement and
unbound preview installation set selected=false immediately. Modal drafts do not
affect this boolean; Window completion can change it, Field completion cannot.

Add `Renderer::set_scene_selected(&mut self, selected: bool)` forwarding to
`Scene::set_selected(&mut self, selected: bool)`; renderer stores only a derived
presentation boolean, never document ids or independent selection authority.
Update it after every authoritative selection change and mesh install, including
when selection-only UI composition fails, and request a redraw when it changes.
Reapply current derived state when a renderer becomes available.

In scene.rs append `selection: vec4<f32>` to SceneUniforms, with x=1.10 when
selected and x=1.0 otherwise, yzw zero. Expand the current 96-byte allocation,
both minimum-binding sizes and packed bytes to 112 bytes. Keep identical field
order in scene.wgsl, scene_lines.wgsl and scene_points.wgsl. Each existing geometry
fragment entry point clamps RGB times selection.x after its existing color/lighting
calculation; depth-only work is untouched. No selection buffer, kernel call, mesh
rebuild, draw call or extra rendering pass is needed. The one ASCII UI draw call
and UI palette shader remain untouched.

Implementation of this section follows the explicit architecture exception in
ARCHITECTURE.md §§3.5–3.6.
