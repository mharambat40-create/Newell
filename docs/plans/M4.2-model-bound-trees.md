### 3.2 Minimal folder metadata

Keep Document::features() -> &[(FeatureId, Feature)] as authoritative operation order.
Add:
```rust
pub enum HistoryNodeId { Operation(FeatureId), Folder(FolderId) }
pub struct HistoryLayoutRow { pub node: HistoryNodeId, pub depth: u32 }
pub struct FeatureFolder { /* private id and full name, read-only accessors */ }

pub fn history_layout(&self) -> &[HistoryLayoutRow];
pub fn folder(&self, id: FolderId) -> Option<&FeatureFolder>;
pub fn create_folder(&mut self, name: String) -> Result<FolderId, ModelError>;
pub fn set_history_layout(&mut self, rows: Vec<HistoryLayoutRow>)
    -> Result<bool, ModelError>;
```

create_folder creates a named empty folder and appends its row at root depth 0.
set_history_layout is the concrete grouping API: only metadata changes; it must
contain every existing folder and operation exactly once. First row depth is 0;
depth can increase only by one and only below a Folder. Operation rows have no
children. Filtering out folders must produce exactly Document::features() order.
Unknown/duplicate/missing ids, invalid nesting or attempts to reorder operations
fail atomically. Nested and empty folders are valid; no name has structural meaning.

This flat preorder metadata is document data, not a retained widget tree. Grouping
cannot reorder/evaluate operations or create geometry. Existing documents with no
folders initialize layout to their operation order at depth 0.

### 3.3 Inserting an existing command result at a history gap

Add commit_extrude_before(spec, before: Option<FeatureId>) to Document and
CommandController::confirm_before(document, before). Existing commit_extrude/confirm
delegate with None (End). With Some(id), resolve its history index k; an absent id
returns UnknownFeature before any other validation. At End, k = features().len().

**Read-only reference preflight.** Add:
```rust
pub enum ExtrudeReference { Profile, MergeScope { index: usize } }
pub fn validate_extrude_insertion(
    &self, spec: &ExtrudeSpec, before: Option<FeatureId>
) -> Result<(), ModelError>; // Document method; changes no state
```

Check profile when Some first, then EVERY merge_scope entry in vector order,
including duplicates and entries supplied when merge_with_all is true. None/empty
adds no explicit reference; existing scalar/termination/merge validation still runs.
For each referenced EntityId:
1. Require its entity record and exactly one producer in committed features/outputs.
   Missing record returns UnknownReferencedEntity { entity, reference }.
   A record with no unique producer returns InvalidEntityProducer { entity }.
2. Resolve the producer's history index p. Require p < k. Otherwise return
   ReferenceNotBeforeInsertion { entity, producer: FeatureId, reference,
   insertion_index: usize }. Equality is a forward reference too.

Expose these precise ModelError variants with normal thiserror diagnostics. The
first failing reference determines the error (profile, then merge-scope index).
After references, run existing validate_extrude scalar/termination/merge checks
and checked model ID-capacity preflight; validate_extrude_insertion returns any
IdentityExhausted error read-only as well. No DAG/rebinding framework or kernel query
is introduced: a read-only walk of features and ordered outputs supplies producer
positions. App can call this same
preflight; enforcement remains in Document so direct model callers cannot bypass it.

Only after successful validation and checked ID-capacity preflight may
commit_extrude_before allocate ids/records and insert the new feature immediately
before k. Its layout row goes immediately before the target operation at that
operation's depth/parent. At End append a root operation after all layout rows.
The DISPLAY position in §5 does not change this existing parent rule: a cursor
displayed between folders may still insert before the successor operation inside
its parent. Operation insertion order and separator placement are distinct.

CommandController::confirm_before validates its current draft before changing
state/preview. It cancels the command only AFTER Document insertion succeeds.
On a reference, boundary, scalar or allocation error, Document features/entities,
all allocation counters, command state and preview are exactly unchanged. App/session
preflight must likewise precede edit_extrude, cancel and notification publication;
§6.3 specifies how to adapt the latest UI draft without violating that rule.

Only history metadata/output creation changes here. No recomputation, geometry
rollback, dependent feature rebinding or history-edit command is implemented.

## 5. Per-window presentation and insertion cursor

### 5.1 Default live initialization

On first real projection/replacement: expand Features root, Elements root and Bodies.
All folders, Surfaces and Construct initially collapsed. Empty branches are leaves
with their expansion preference remembered for a later nonempty refresh. Clear focus,
selection, scroll and Rename. Initialize a PlacedHistoryGap { insertion: End,
display: EndOfTree }, not the penultimate operation.

README_UI.md §26 authorizes drawing the existing separator after all history rows,
including empty/one-operation history while Features is expanded. A canonical
Before(operation) location is BeforeNode(that operation), after its ancestor
headers at its depth. Selecting an explicit structural boundary uses its specified
location instead. Expand ancestors only if that chosen location would be hidden.
No new glyph, icon or selectable node is introduced.

### 5.2 Insertion anchor versus structural display location

TreePresentation stores a PlacedHistoryGap. The insertion component is the only
value passed to model commit; display locates the separator in the flat hierarchy.
Use this label-independent resolver in shell/tree.rs:
- BeforeNode(Operation(id)): anchor Before(id), line directly before that row.
- BeforeNode(Folder(id)): anchor before the first operation at or after the folder's
  opening row in preorder (including descendants); End if none follows. The line is
  before the folder HEADER and has that header's depth/ancestor guides.
- AfterSubtree(node): anchor before the first operation after that complete subtree;
  End if none follows. Draw the line after that subtree, at the node's depth, BEFORE
  any following sibling folder header. Empty folders follow the same rule.
- EndOfTree: anchor End; line follows all structural rows, at root-child depth 1.

A pair is valid only if resolving display produces its stored insertion anchor.
Do not merge distinct display locations just because they have the same anchor.
BeforeNode(second folder) and AfterSubtree(first folder) at a shared sibling boundary
produce the same line; retain the selected variant for identity-based reconciliation.
Validate ExplicitGaps and the initial pair with this resolver.

Live dragging:
1. Drop over an operation: select AfterSubtree(that operation) and its resolved anchor.
2. Drop over a folder: select AfterSubtree(that folder), including when collapsed.
3. Above all history items: select BeforeNode(first structural item), anchored before
   the first operation, or End for a layout containing only empty folders.
4. Below all items: select End/EndOfTree. Empty history has only the End insertion
   anchor; any explicit empty-folder placement still resolves to End.
Reference dragging selects only its explicit pairs from §4.3 and keeps their displays.

Required two-folder case: roots A{operation 1}, B{operation 2}. Dropping on A gives
Before(operation 2) + AfterSubtree(Folder(A)). The separator is between A's closing
subtree row and B's HEADER, not between B's header and operation 2. The equivalent
BeforeNode(Folder(B)) placement resolves to the same insertion boundary. Renaming
A/B changes neither anchor nor location. A real commit at this anchor inserts before
operation 2, with B as parent per §3.3; display location never silently changes that
model parent rule.

Keep top-level separator glyphs exact and use the selected structural location's
depth/continuing guides for a nested separator. Collapsing a folder that contains
the display location moves the local pair to AfterSubtree(that folder), recomputing
its anchor. Collapsing Features hides the line but retains the pair.

At start of an Extrude Editing session, App captures document identity and the
INSERTION anchor only. Moving the cursor during that session affects the next
command. Confirm uses the captured anchor after §3.3 validation; after success put
the local cursor at AfterSubtree(new operation), with its resolved anchor.
Deleting/replacing the captured insertion target cancels the pending command.
Moving/dragging the cursor never mutates Document or rolls back geometry.

### 5.3 Refresh reconciliation

For a same-document refresh, reconcile by tagged semantic identity:
- Expansion survives for surviving folders/roots/groups; new folders use collapsed.
- Selection survives, including inside a collapsed/offscreen branch; removed targets
  clear. Clicking a row changes only tree-local selection/focus, with no new visual.
- Focus follows its target. If a branch is collapsed through user activation, focus
  moves to that branch. A removed focus clears. While a modal is open, never replace
  modal focus with a tree WidgetId.
- First preserve the top visible semantic row of each pane, then clamp its offset.
  If it vanished, choose the first surviving successor in the OLD visible order,
  else the nearest surviving predecessor, else zero.
- On projection refresh, ensuring the focused row is visible takes precedence over
  top-row anchoring if both cannot be satisfied. Wheel scrolling may leave semantic
  focus offscreen; clear its visible InteractionState id until it becomes visible.
  Enter/Space with no visible focused row does nothing; Tab starts at the first
  visible row (BackTab at the last).
- Names and visibility always come from the new projection; no local override wins.
- The insertion anchor Before(id) follows a surviving operation on reorder. Retain
  the display node/location only if it survives and still resolves to that anchor.
  Otherwise canonicalize to BeforeNode(that operation), revealing its ancestors.
  If the anchor operation disappears, use the first surviving successor in the OLD
  operation order and its canonical display, otherwise End/EndOfTree. For End, retain
  a surviving explicit display only while it still resolves to End, else EndOfTree.
- Full identical projection is a no-op. Label/visibility changes still redraw when
  needed even if they do not change the hit map/generation.

On document replacement use a fresh namespace. Reset all local state and cursor,
close old Rename, clear pending intents/double-clicks, cancel captured tree drag and
draft insertion target; never reconcile raw id zero to another document's id zero.
Keep unrelated window scale/theme/panel widths and non-tree UI state.

### 5.4 Scrolling and established interactions

Wheel steps over a tree pane move that pane by whole visible lines, clamped with
saturating arithmetic to max(0, visible_line_count - pane_line_count). Preserve
existing wheel direction. No new scrollbar artwork. Root rows scroll with the list.
Selection modal retains first priority; other modals, active menus, resizing and
captured drags block underlying tree scrolling. A tree owns the wheel even at its
scroll limit: no viewport fall-through. Use existing O(1) grid/layout admission.

Markers toggle expansion and focus the row. Names/row padding select and focus.
Enter/Space toggles a focused branch and preserves existing leaf activation semantics.
Squares emit SetVisibility with expected old and desired new values; no optimistic
glyph change or keyboard visibility shortcut. Rename eligibility is named operations,
folders (C3), and Bodies entities; Surface/Construct entity Rename remains unintroduced.
All names remain full in state. No tree hover, focus glyph or selection inversion.

## 6. Document notifications, commands and application delivery

### 6.1 DocumentSession

Create private app module document.rs. DocumentSession owns the one current Document,
DocumentInstanceId, checked monotonic replacement-id allocator and revision. It is
the long-lived session for this App; replace its Document, never recreate the session
to reset identities. No global UI singleton.

subscribe() returns std::sync::mpsc::Receiver<DocumentNotification>; the session
stores senders and removes disconnected ones on publication. Event:
```rust
enum DocumentNotification {
    Changed { document: DocumentInstanceId, revision: u64 },
    Replaced { document: DocumentInstanceId, revision: u64 },
}
```

### 6.2 Subscriber, pending obligation and bounded retry

App owns the session, this window's Receiver and ProjectionSync state (private type
in document.rs). ProjectionSync::acknowledged is the sole last-applied acknowledgment:
```rust
struct PendingProjection {
    document: DocumentInstanceId,
    revision: u64,
    attempts: u8,                 // 0, 1, or 2 for this attempt cycle
    retry_at: Option<Instant>,
    suspended: bool,
}
struct ProjectionSync {
    acknowledged: Option<(DocumentInstanceId, u64)>,
    pending: Option<PendingProjection>,
}
enum ProjectionTrigger { Notification, RetryDeadline, UserActivation, LayoutPublished }
```

Pending records the obligation to publish, not a consumed event. App owns the clock;
all helpers receive now: Instant for deterministic tests. No new timer thread,
channel type, queue framework or dependency is needed.

**Notification recording/coalescing, before any attempt:**
1. Drain Receiver and ignore identities other than session.identity(). For the current
   identity take the highest notified revision greater than acknowledged. Compare
   revision numbers only within the SAME identity; a new identity supersedes the old
   acknowledgment even when its revision resets to zero. Also compare
   session.revision() with acknowledgment when seeding startup/replacement so revision
   zero does not depend on subscription timing.
2. Store/raise pending to the CURRENT session identity/revision before attempting
   conversion. Coalesce queued older revisions into current state; never tag a current
   projection with an older event revision.
3. A higher revision or replacement resets pending attempts to 0, retry_at None and
   suspended false. Duplicate/lower events for the same pair cannot reset attempts,
   extend a deadline, wake a suspended obligation or create another attempt.
4. Replacement immediately discards the old pending identity/deadline and invalidates
   old document command/drag/double-click authorization. Keep the last valid frame
   until a replacement candidate publishes. While the acknowledged frame's identity
   differs from the session identity, App rejects its old-namespace tree intents and
   does not arm/confirm commands from that old shell. Passive retry may still recover.
   Old queued events never resurrect the discarded identity.

**Attempt/acknowledgment:**
- Increment attempts immediately before an invocation (0 -> 1, or 1 -> 2 when due).
  Do not reset/decrement it on failure. With no pending obligation return no Update.
- With attempts 0 attempt once immediately on notification/startup. project_document
  and ShellController::set_tree_projection prepare/publish atomically. On success,
  acknowledge the actual session (identity,revision), clear pending/deadline, merge
  Update and call App::apply. No acknowledgment is made merely by draining a channel.
- On failure retain the pending identity/revision and previous acknowledgment, grid,
  projection, hit map and generation. Report the failure once per attempted failure;
  do not report a committed model mutation as rolled back.
- Failure of attempt 1 schedules exactly ONE automatic retry at now + 100 ms.
  Retain attempts=1, suspended=false. Before the deadline, idle/status/redraw/pointer
  events do not attempt again.
- At/after that deadline attempt 2 once. Clear retry_at BEFORE invoking conversion.
  Success clears pending. A second failure retains the dirty pair with attempts=2,
  suspended=true, retry_at=None. There is no third automatic attempt for this cycle.

**Bounded rearming and event-loop wiring:**
Add App::poll_document_projection(now, trigger) -> Update and
next_document_retry_deadline() -> Option<Instant>. The poll first records/coalesces
new notifications as above, then applies the attempt rules. A suspended pair is
rearmed only by a new higher revision/replacement, an actual primary-button/key
activation, or a successful external layout/scale publication. Rearming sets attempts
to 0 and permits one immediate attempt plus at most one timed retry. Passive pointer
motion, FPS/progress ticks, monitor polling without a layout change, redraws and
duplicate notifications never rearm. A non-suspended pair already waiting for its
deadline is not reset by these activation triggers.

In App::about_to_wait, poll once with RetryDeadline when due, apply its Update, then
include next_document_retry_deadline in the existing minimum wake calculation with
status/monitor/presentation deadlines. Set ControlFlow::WaitUntil for the earliest
future deadline; never leave a consumed/expired retry deadline scheduled. Hidden
windows omit this wakeup and retain pending; the first visible/restored turn performs
a due attempt once. Do not reset attempt count on restore. No busy retry/redraw loop.
A successful layout trigger is external input, not an effect of App::apply itself;
set a private App::layout_retry_rearm_pending flag only after a genuine successful
resize_shell or apply_rescale/commit_metrics publication, then take/clear that flag
at about_to_wait to supply LayoutPublished. Identical layouts, model projection
publication and App::apply cannot set it. This avoids recursive polling from apply.

Tests use a cfg(test) fail_next_projection flag at the preparation boundary (before
controller publication), not invalid model data or a production mutation escape.
With an injected one-shot failure at t, assert pending remains and the old frame
is unchanged; no attempt before t+100 ms; at t+100 ms recovery publishes/acknowledges
without any further document mutation/event. Inject two failures and assert suspension,
no deadline/attempt on repeated idle ticks, and one new bounded cycle only on the
specified rearm triggers. Coalescing/replacement tests verify stale deadlines/acks.

**Per-input order:**
App::finish_shell_input(update) runs after each pointer/key activation and before
another translated key: validate/take its tree intent; apply the named session
mutation; run the confirmation adapter (§6.3); record notifications/poll with
UserActivation; merge the resulting Update; call App::apply once. Source/id/type/
generation checks still precede model mutation. A retry-only event does not replay
the original click, command, Rename completion or notification.

Startup populates session once, creates/assigns the empty application shell/window,
subscribes and explicitly seeds pending with current identity/revision. Attempt the
initial projection before show. On failure retain the valid empty frame and pending
timer so the first normal visible event-loop turn can recover. Remove the one-shot
label adapter; resolve scene_entity from the base feature's first real output.
Preserve viewport behavior and renderer/kernel ownership.

## 7. Published hit map, generation and atomic transitions

### 7.1 Exact published map and bounded ids

A published frame comprises CellGrid, visible tree slot table, routing policy,
GridMetrics and ProjectionGeneration. Derive routing from final composition AFTER
menus/overlays, including shared-border ownership and modal/menu input gates.
A tree is not actionable behind any active modal/menu, including uncovered cells.

For every physical pixel, its tree-related route is None or:
- (TreeTarget, TreePart::{Row,Marker,Check,Name}) for a currently actionable cell;
- (Playhead target, Drag) for the separator;
- (Rename session identity, modal control part) while the tree's Rename owns input.
Layout drag admission is compared separately with its current geometry. Thus the
map includes parts, clipping, metrics, occlusion and input precedence, not merely
a list of visible semantic rows.

Reuse WidgetIds by visible slot. Reserve TREE_SLOT_CAP = newell_ui::MAX_CELLS ids
per pane, four parts each, after the existing menu ranges; reserve playhead separately,
then place Action Box/overlay/window ids after that range. Checked/compile-time
arithmetic proves these u32 ranges disjoint. Only visible rows allocate table entries;
there is no feature count limit and no millions-of-entries table allocation.
O(1) division/modulo decodes pane/slot/part, then direct vector indexing resolves
the target. A stale WidgetId alone never authorizes an action.

Keep existing grid as the per-cell ownership table; do not allocate a duplicate
per-pixel map. Compare old/new final grid ownership, slot targets, routing policy
and metrics at publication to determine whether the effective map above changed.
Composition/publication may iterate cells; pointer lookup never scans bounds.

### 7.2 Generation and publication ownership

ShellState owns semantic TreePresentation. ShellController owns the authoritative
published generation/frame because it owns final grid and metrics. The UI action
interface accepts captured tokens, and direct UI unit-test drivers use the same
frame/token preparation helper with unit metrics. Pure ShellState::compose remains
read-only; generation never advances merely because compose was called.

Capture TreeHitToken { generation, target, part } from the PUBLISHED map when a
pointer hit or keyboard activation occurs. Keep these fields through queued actions,
double-click recognition and Rename session origin. Before a local action check
equality with the current map. Before delivery to App check current generation,
namespace and target; App also checks model existence/type/expected old value.

For each changed input/projection, prepare candidate shell/slot table/grid and
routing policy without publishing them. If the effective map changed, checked-add
generation. Publish all together only after successful preparation. On error discard
candidate UI changes and pending intents; old published frame remains consistent.

overlay transitions, panel visibility/split/width, scroll and playhead movements.

### 7.3 Ordered Rename lifecycle and narrow close certificate

TreeIntent has private authorization fields and public getters:
generation (currently authorized frame), origin_generation (captured hit),
target and kind. Kinds are Rename { source_name, name } and
SetVisibility { expected_visible, visible }. UI consumers cannot create a certificate
by passing only a WidgetId. Each Rename session has a checked, never-reused local id.

Order is normative:

1. Second eligible name press validates the captured name token and double-click pair
   (same semantic name, same published generation, <=500 ms, no intervening target).
   Store origin token, semantic return-focus target and full source name.
2. Open Rename on a candidate shell. Publish modal map/generation. Bind the owned
   session to that newly published generation; invalidate every other prior token.
3. Editing preserves full text. A same-document projection refresh keeps the session
   only if target/type/source name still agree; otherwise cancel. Rebind only this
   owned session after successful publication. Window/layout changes may likewise
   keep and rebind this session if its model source is unchanged. Replacement cancels.
4. On modal OK/Enter, validate the current modal-control token, session id, current
   bound generation, target and source name BEFORE closing. Nonempty validated text
   becomes a staged Rename completion for that exact session. Cancel emits nothing.
5. Prepare/publish the modal close and semantic focus restoration. This changes
   generation. The just-validated completion alone receives a private one-use
   close certificate recording (session, validated generation, closing generation).
   Deliver a TreeIntent authorized at the closing generation, retaining its ORIGINAL
   origin_generation. This is an explicit transition, not accepting an old hit again.
6. App takes it synchronously via finish_shell_input before another input. Accept
   only if the current published generation is still the recorded closing generation,
   and namespace/type/source name still match. Any intervening mapping change drops it.
   Discard the certificate after one delivery, including a failed/no-op model edit.

Unrelated checkbox/name tokens are never rebased. Escape, target removal and document
replacement cannot produce the certificate. A stale modal button from another
session cannot confirm the current one. Semantic focus restoration overrides the
overlay's remembered positional WidgetId; removed targets restore no tree focus.

### 7.4 Owned drag continuation across self-generated frames

Keep existing primary-button capture behavior; do not require a fresh hit on each
CursorMoved event. Add private controller types:
```rust
struct DragCaptureId(u64); // checked monotonic allocation, never reused
struct OwnedTreeDrag {
    id: DragCaptureId,
    document: Option<TreeDocumentId>,
    kind: TreeDragKind, // Playhead, NavigationDivider or FeaturesElementsDivider
    origin_generation: ProjectionGeneration,
    bound_generation: ProjectionGeneration,
}
enum FrameCause { External, OwnedDrag(DragCaptureId) }
```

Capture on a primary press only after validating the published handle hit/generation,
input precedence and current document. Store stable kind/document and fresh capture
id, origin_generation and bound_generation=current. Navigation/split captures before
a document projection may use document=None; installing a document is external and
cancels them. Counter exhaustion returns UiError::InteractionIdentityExhausted and
does not start a capture. Selection-list thumb capture retains its established path.

For each pointer movement during capture:
1. Check initiating button still owned, no cancellation condition, current generation
   equals bound_generation, same document, and same logical handle kind is available.
   Use the existing captured-coordinate transform; do NOT hit-test the old handle
   cell again or require the moved pointer to be over that handle.
2. Prepare movement/state/grid with FrameCause::OwnedDrag(exact capture id), supplied
   only by this pointer-movement path. Apply the ordinary checked generation advance
   if the effective hit map changes.
3. On successful publication, retain capture id/document/kind/origin_generation and
   rebind bound_generation to the new published generation in the SAME transaction.
   Unchanged/no-op movement retains the binding. Failed preparation leaves the old
   frame and old capture binding intact, with no partial movement.
4. The next movement validates that rebound capture. This repeats for any number
   of movements while held. A stale one-shot token remains invalid; the drag receives
   no right to emit Rename, visibility or model mutation intents.

External cancellation is explicit: pointer exit, focus loss, release of the initiating
primary button, another primary press, document replacement, any changed document
projection (including membership/order/grouping refresh), overlay/menu opening or
input-owner interruption, window resize/metric/scale publication, external panel
visibility/width/split changes, or any OTHER effective map change cancels capture.
A replacement cancels its authorization immediately even if the replacement's UI
projection is still pending/failing. Do not reacquire on a later pointer move; a
fresh press is required. Status-only redraw, hover glyph changes and an identical
projection/map do not cancel. Clear double-click state when capture starts.

Only the active exact id may use OwnedDrag publication. A callback, queued old move,
external resize or different capture cannot label its update OwnedDrag to evade
cancellation. Clear capture before publishing an External transition that requires
cancellation. A later release is consumed as the end of the canceled gesture and
does not activate a newly exposed widget.

Required controller tests: for EACH playhead, Navigation divider and pane divider,
press once and perform at least three distinct movements before release. Check
the geometry/cursor at every movement, generation advances as appropriate and
dragging stays true until release. Then repeat and interrupt after several moves
with document replacement and separately an overlay/menu; assert dragging=false,
later movements/releases act on nothing and a new press is required. Add external
resize/metric cancellation and harmless status/no-op preservation cases. Existing
multi-move divider tests remain unchanged in behavior.

This is continuation of an owned gesture, distinct from §7.3's one-use Rename-close
certificate. These are the only permitted owned transitions across generations;
neither authorizes arbitrary stale hits.

## 13. Measurable acceptance criteria

1. Actual application trees contain only real projected document rows; reference mock
   names/topology never leak into new_application startup.
2. UI depends on neither newell-model nor newell-kernel. Folder/operation/entity ids
   remain distinct and replacement namespaces never repeat.
3. Features follows operation history with folders preserving that order. Live labels
   are Bodies(N), Surfaces(N), Construct under clarified README_UI.md; counts/order include all
   ordered outputs regardless of visibility, with all empty groups present.
4. The unchanged historical reference fixture still passes exact panel and snapshot
   assertions, including nesting, expansion, Sketch squares and initial playhead.
5. Live End initialization and insertion anchors/structural placement work as §5,
   including the unchanged reference first gap before Hub_Features and a gap between
   two folders. Display location never changes the operation insertion boundary.
6. Each successful persistent mutation publishes exactly one event; failed/no-op/
   preview/Cancel publishes none. One consumed confirmation creates at most one feature.
7. Changes propagate producer -> subscriber -> real projection -> controller ->
   App::apply. A scrolled grid uploaded/published by the app equals its hit-tested grid.
8. Every hit carries target, part and captured generation. Parts/occlusion/metrics
   changes advance generation; stale cells and prior-document targets cannot act.
   Rename's own certified close delivers once without authorizing unrelated old hits;
   owned playhead/divider captures survive at least three own moves while held and
   cancel on replacement/overlay/external interruption without stale continuation.
9. Long names round-trip intact through model, modal, confirmation and refresh.
10. Refresh/reorder/removal tests prove semantic state reconciliation at the declared
    boundary. Tests never pretend unavailable real model APIs exist.
11. Missing/forward explicit entity references fail before command/CAD state changes,
    ID allocation or notification. Strictly earlier references succeed; error precedence
    and all unchanged state/counters/revision are covered by model/session tests.
12. A failed projection leaves a pending obligation and the last valid frame; one
    automatic retry at +100 ms recovers without another document mutation. Two failed
    attempts suspend without an idle retry loop, and coalescing/replacement/acknowledgment
    follow §6.2 exactly.
13. Automated verification is green; inherited failures and pending manual acceptance
    are separately reported. No snapshots are auto-updated and the index is unchanged.
