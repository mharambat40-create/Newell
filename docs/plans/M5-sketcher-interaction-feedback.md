## 3. Pointer-driven magnetic placement

**Interpretation of “auto-clip.”** No runtime or canonical Sketch feature uses that name. The implemented proximity trigger is magnetic placement in `sketch/snap.rs` (`active_slot`, `target_hits`, `placement`, `update_snap`, `magnetic_click`). Slice in the Sketch Action Box is inert and M5 D2 describes it as background-model plane clipping. This revision treats auto-clip as magnetic placement. If the request means a separate clipping feature, its trigger is unspecified and this section needs a product correction before implementation.

Today `App::sketch_pointer` uses `scene_pointer`, shell admission, navigation masks and the support ray. `sketch_strokes` and modifier changes update the proposal, and placement revalidates on the final click. Existing point/curve proximity already uses physical distance from the raw pointer to projected contact, 8 logical px to acquire and 12 to retain. Active slots limit the feature to Point, Line and circular Arc workflows, and some directional inference uses adjusted geometry. Extend the existing path.

1. Use a single Controller sample of raw viewport pixel, raw plane hit, scale, camera/layout generation and modifiers. Recompute on pointer, modifier or compatible camera/layout changes and revalidate on click. Keep the sample distinct from the proposed local placement and from its rendered endpoint. Clear the live proposal when admission is lost. Rendering consumes the resulting proposal without deriving another pointer from the preview.
2. In every Sketch tool, including Select and operand-only stages, run the same admitted proximity query against the shared handles and existing analytic finite-curve contacts. Keep the existing point-over-curve priority and hysteresis. Display the existing contact diamond as a cue. In coordinate placement stages (draw, copy, pattern/transform, geometric edit intervals/directions and label placement), pass the eligible snapped coordinate through the same preview and click handler. Keep the raw coordinate if the snapped coordinate invalidates that stage. In semantic entity-selection stages, keep picking at the raw cursor with the tool's existing role and ambiguity rules. Projected/Intersect acceptance uses its existing feature/reference flow. During direct dragging the temporary solver target comes from the raw sample. Ctrl bypasses placement and automatic proposals and leaves explicit tangent input intact. Active menu, modal or incompatible capture suppresses cues.
3. For Line, measure target acquisition and retention from raw pointer pixels. Test axis and inferred tangent acquisition/release against the raw plane direction or raw candidate tangent (5°/8°). Apply established hit precedence and require compatibility before combining snapped contact, tangent and axis. An axis-aligned snapped segment cannot retroactively qualify its pointer for alignment. Keep persistent automatic joins limited to the existing supported Point/Line/circular Arc relation paths. Other tools consume a coordinate without recording a new relation. Gates that require true coincidence continue to use modeling tolerances.

## 4. Select drag and worker contract

### Gesture and transaction

Extend the primary press in `app.rs` and the edit state in `sketch.rs` with a frozen Select hit and press certificate. A press on an eligible handle or stroke selects that target once it crosses the existing 4-logical-pixel threshold. A below-threshold release retains ordinary Select click behavior, including clearing on empty space. Empty-space drag and read-only hits create no solve. Freeze the base draft and press ray hit, selected handle or body anchor, camera, support, position offset and display scale. The request target is the original handle/anchor plus raw local pointer displacement from press, so picking within slop does not jump. A captured drag may cross viewport UI within the window using the frozen support ray without repicking or routing that release to a control. Cancel on pointer exit, invalid ray, focus loss, occlusion, resize/DPI or layout change, menu/modal takeover, navigation invalidation, source version change, tool/session change, explicit Cancel or Escape. Consume the matching release and Escape before ordinary Select handling. A new navigation gesture cannot acquire while this pointer capture owns input.

| Hit | Pose or target for the solve |
|---|---|
| Explicit point | Target its two local coordinates. |
| Line body | Request rigid translation using the grabbed point as anchor. Preserve its vector when feasible. In a joined solve, target its frozen segment fraction and prefer the translated endpoint pair after minimizing pointer error. |
| Line endpoint | Target that endpoint. Prefer keeping the opposite endpoint at its seed where the equations allow. |
| Circular arc body / center | Request translation with the original radius and signed sweep preferred. For a joined body use the analytic point at the frozen arc fraction. For the center target the analytic center. |
| Circular arc endpoint | Target the analytic endpoint. Prefer the seed center and opposite endpoint where feasible. Preserve sweep sign and valid open-arc branch. |
| Circle, ellipse or other independent shape / its non-endpoint marker | Translate the recipe rigidly in plane, anchored at the grabbed point or handle. Radius, axes, group shape, text size and internal controls retain their definitions. |
| Other open-curve endpoint | Translate the whole curve by its endpoint. No control-polygon reshaping in this slice. |
| Origin, linked geometry, associative instance or Formula-owned generated result | Read-only. Selectable as applicable. Use the current detach or master workflow for edits. A segment with a Formula driving its length remains movable subject to that value. |

Factor the finite support-ray calculation out of `Navigation::sketch_point` so only an already captured drag can use it beyond exposed pixels. Keep accepted `edit.recipe` as the seed and render a separate provisional recipe. Preview all affected geometry, instances, handles and measured annotations from the same display recipe. Disable draft OK and other draft edits during capture and final validation. Releasing freezes exactly the release-position request (reuse a matching solved preview only with an exact certificate match). Install its validated recipe once, consume the token, recompute readiness and leave Select active. A failed current solve or cancellation discards the provisional recipe and retains the accepted draft. A fully constrained target produces no edit. Document publication still goes through Sketch OK.

### Model solve

Add `newell-model/src/sketch/drag.rs`, called by a dedicated `SketchSolve` purpose in `geometry_worker.rs`. Reuse existing analytic model functions, tolerances and validators. `solve_constraints` in `joins.rs` currently does anchored, directed correction. `solve_segment_equations_where` in `dimensions.rs` fixes a line start and rewrites its end. Neither is a projection to a pointer objective. Keep both existing entry points for their current callers. Use the following bounded drag path.

1. For shapes outside an equation/join component, apply the requested analytic edit directly. Translate DrawGeometry using the existing similarity transform. For legacy axis-aligned Rectangle translate min/max in place so corner roles stay valid. For EditedLine update the stored endpoints and preserve the key and provenance fields. The generic copy/transform helper converts both variants and is unsuitable for these in-place edits. A free line endpoint preserves the other endpoint. For a free arc endpoint, use the seed center, put the dragged endpoint at the requested vector, retain the opposite endpoint's direction and carry both endpoints on the resulting common radius. Use the existing signed sweep branch and reject zero radius, zero sweep or branch crossing. Validate before producing a candidate.
2. For a constrained component, collect the transitive closure of shared keys through existing joins, and attach all segment equations on these keys. Parameterize point UV, line endpoint UV pairs, circular arc center/radius/start angle/signed sweep, and circular ellipse center with fixed shape for the currently supported center join (only its center participates). Origin and guarded generated entities are constants. Use one bounded contact parameter per PointOnCurve record as internal solve state. Constrain the point to the analytic `curve_at` target with `t ∈ [0,1]`, treating active bounds as inequalities that can release inward. The parameter records the solved contact and contributes no independent geometric handle. Build residuals for H/V, resolved driving length, two-coordinate Coincident, PointOnCurve and Tangent endpoint coincidence plus normalized tangent cross product. Retain the stored tangent dot-sign branch. Driven measurements contribute zero equations.
3. Normalize lengths around a component-local origin using a characteristic nonzero length, and keep angular residuals dimensionless. Starting from the feasible seed, use bounded local constrained least squares. For each iteration, form the hard-equation Jacobian by scaled finite differences, use pivoted orthogonalization of its rows to find a consistent particular step and a null space, then minimize the two-coordinate pointer residual in that null space. Use remaining null space for the preferred seed/rigid pose. Rank uses hard equations and active bounds, independent of the pointer residual and convergence. For active bound rows, try a feasible inward direction before treating the bound as fixed. Backtrack step length on nonfinite, branch-changing, rank-inconsistent or non-improving trials, restoring hard feasibility with the same particular-step projection. Accept when hard residuals pass the existing unscaled validators and the feasible pointer improvement is below current geometric precision. A rank-deficient system can be consistent. A target with no remaining motion is a no-op even if another member has free DOF. Check actual target mobility and geometry delta, and distinguish a fixed target from numerical failure or a pointer position already at the closest valid point.
4. Bound the first implementation to 64 scalar unknowns including contact parameters and 128 scalar hard rows per coupled solve, with 24 iterations and at most eight backtracking trials per iteration. Larger components return a specific drag diagnostic and retain the draft. Check cancellation during assembly, finite differences, iteration and before reply. Reuse `validate`, `validate_segment_equations` and `validate_joins` through a Model draft-candidate helper. Preserve identities, dimensions, equations, Formula bindings and unaffected records, and refresh only affected PointOnCurve parameters. Reject degenerate shapes and invalid operands. Do not treat an invalid or unconverged trial as a final edit or widen tolerances. No new dependency, alternate solver backend or general M5 scheduler.

## 5. Annotation pipeline

In `sketch.rs::dimension_strokes`, dispatch by typed record rather than label string length. Current code draws H/V, driving length and driven length only, and strokes both outlines of Fira Code glyphs at the geometry width. `snap.rs::label_strokes` and `join_strokes` use the same outline approach. Replace outline strokes on these three annotation paths with filled Fira Code Regular glyph coverage. Model Sketch Text remains outline geometry. Use 9 logical px cap height for relation letters (including magnetic proposals), 10 for numeric values, with rounded physical baselines and native-scale glyph coverage. Target regular stems visually comparable to a 1.5 px curve at 1× and 2×. Keep holes, minus, decimal point, unit suffix and driven parentheses readable. Keep the existing magnetic label position, edge flip, contact and trace rules.

- Values use `Document::sketch_measurement` / typed driving values and `Quantity::display` in `mm` or `deg`; preserve signed branch and driven parentheses. Support the current non-Length driven record types with resolved analytic operands. Use a measured-span dimension line for direct or component distance, leaders for radius/diameter and arc length, and two witness rays and a dimension arc for Angle. For Angle, use the measured segment's start as the vertex and translate the reference direction (local +U for a single segment) through it. Draw the oriented sweep from reference to measured direction as computed by the measurement, showing absolute or signed value per record. Preserve explicit stored label placement; use an offset default at the sweep midpoint with a 20 logical px radius. Choose the radius from stored placement if present, with 20 px minimum. Anchor the label to the arc by a leader if offset. No new angular authoring command is required. Skip unresolved annotation geometry without removing its record.
- Dimension lines, witness/extension lines, leaders, arcs and arrow/tick strokes all use ordinary 1.5 logical px Text ink. Use small open 5-logical-pixel ticks or arrowheads where the span admits them. Reserve a 2-logical-pixel gap around the label bounds where ink would cross text. Relation letters need no leader. Keep current annotation placement and visibility behavior for existing records and do not activate inert Action Box controls as part of styling.
- In `newell-render/src/{sketch.rs,sketch.wgsl,renderer.rs,lib.rs}`, extend the immutable Sketch frame to carry strokes, marker discs/rings and screen label runs. Reuse `ab_glyph` and the existing font asset. Follow the coverage raster approach in `navigation_labels.rs` by caching printable annotation glyph masks and metrics at the two physical cap sizes, rebuilding on display-scale change. Use native physical-pixel coverage quads in the existing Sketch vertex buffer with coverage alpha, or one sampled mask binding with solid-ink vertices in the same indexed/scissored batch. Use the former for this slice to avoid a new texture resource. Render glyphs once at each glyph pixel, blend Text ink by coverage, and apply the same clipping and depth order. Keep one Sketch draw per exposed rectangle and the existing single ASCII draw. No UI cell scaling changes. Layer annotations and markers over ordinary geometry within the Sketch batch, with live proposal cues last.
