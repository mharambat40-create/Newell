## Propose and place

- **Point and Line.** Point places one point. Line can attach at either endpoint. For a free Line end, project exactly onto the U or V axis through the start when angular error is at most 5°. Release above 8°. Keep zero-length placements invalid. A continued Line starts at the previous segment's solved End and proposes Coincident to its stable endpoint.
- **3 Points Arc.** Start and End accept positional attachments. Keep the through click as a shape input. Compare the unsnapped provisional arc's analytic start tangent with the tangent at an attached Line or circular Arc endpoint. For a free End, build the tangent circle through Start and the through point, then project End onto that circle with the original sweep direction and through-point order. For an exact End target, offer Tangent only if the same branch passes through it. If the correction is degenerate, retain the ordinary arc candidate.
- **Center Point Arc.** Center, Start and End accept positional attachments. The clicked center and start define the final End locus. Offer inferred start tangency when the provisional arc satisfies the angular test and the chosen center and start already give the exact tangent. Keep the accepted center and start fixed during the final preview. For an End point target, require that it lie on the circle. For an interior target, use the nearest admissible analytic intersection with the End locus.
- **Tangent Arc.** The first click explicitly picks a source endpoint and its analytic tangent. For Line and circular Arc sources, retain the stable endpoint and show Coincident and Tangent together during the gesture. On completion persist both. This tool supplies the tangent exactly. Preserve its existing construction from other supported curve types. Ctrl suppresses automatic records while preserving the explicit source input required by the tool. End accepts a compatible positional attachment.
- **Tangency for Line.** At a free End, project the line onto the tangent through its attached Start. At an exact End target, retain Tangent only when the exact placement satisfies it. Use 5° acquisition and 8° release for inferred tangency on Line and arcs. Compare normalized nonzero tangent directions and retain the accepted relative orientation and arc sweep.
- **Candidates.** Reuse exposed-viewport routing, the existing sketch-space ray and camera projection, stable IDs, resolved sketch traversal and analytic endpoint helpers. Eligible explicit points are the semantic origin, independent points, Line and circular Arc endpoints, and editable circle/arc centers. A finite independent Line or circular Arc interior offers Point on Curve. Resolve a segment contact by projection and an arc contact by bounded signed angle. Exclude endpoints from interior candidates. Admit only operands the production solve can represent. Derived patterns, linked references and formula-controlled primitive shapes remain ineligible. Preserve selection-mode hit rules.
- **Arbitration.** Acquire within 8 logical pixels, retain the same positional target through 12, and convert through the window scale factor once. Rank explicit points ahead of interiors, and interiors ahead of free alignment. Within the active class retain the latched target through release, then choose nearest screen distance, stable geometry ID and point role or interval order. A higher-priority explicit point can preempt a latched interior or alignment. Prefer an attached tangent over axis alignment when they compete at a free Line end. Stack relations only when they share an exact valid placement. Earlier accepted gesture steps stay fixed when ranking the final click.
- **State.** Keep the live proposal and earlier pending attachments on the window-local edit. Recompute on admitted pointer, camera and modifier changes using the same placement calculation for preview and acceptance. Ctrl immediately clears the latch and restores the raw preview. A Ctrl completion click omits the gesture's automatic records, including a chained start or earlier pending attachment. Previously clicked coordinates remain the placement seed. The selection modifier route stays in Select mode. Viewport exit, occlusion and capture clear the live proposal. Tool, focus and layout changes clear unfinished state according to existing gesture rules. Escape follows menu, modal and capture precedence, then cancels the pending placement or solve and keeps completed draft geometry.

## Persistent records and solve

1. Keep H/V in the existing `SegmentEquation` representation. Add a default-empty typed join map on `SketchRecipe`, with stable IDs allocated collision-free alongside the other relation/dimension IDs. Store `Coincident` with two `SketchPointRef` operands, `PointOnCurve` with a point and stable finite-curve operand plus a normalized parameter seed, and `Tangent` with two typed endpoint roles and relative tangent orientation. A tangent join includes incidence. Reuse matching Coincident positional equations for that contact. The Point on Curve parameter can move within the retained bounded curve domain during solve. Keep primitive IDs independent.
2. Use the current worker entry and independent-segment solve for components without joins. For joined components, build stable incidence and include every reachable operand and existing segment equation. For a draw acceptance, hold established geometry at its accepted coordinates and validate the exact new placement. For a subsequent supported edit, take the explicitly edited geometry as the preferred anchor and move dependent geometry where necessary. Process all relations in that component together. Use the existing analytic constructors for the independent point, segment and circular shape blocks. Moving a circle center preserves radius. Moving a circular arc contact can translate the arc at constant radius/sweep. A tangent correction can rotate a free line about its contact or place an arc center on the contact normal with its radius and signed sweep preserved. Include direct H/V and length corrections and bounded point/curve corrections in the same solve.
3. Apply those corrections in a deterministic order with a bounded per-component refinement budget and cancellation checks. Prefer the last accepted shape and branch. Accept immediately if the complete set of residuals passes. Reject a degenerate contact, incompatible anchors or failure to converge within the budget with the affected records and a short diagnostic. Check position residuals against the production length tolerance (`1e-7 mm` in the segment solver) and propose `1e-8 rad` for normalized tangent residuals. Check finite geometry, bounded contact, tangent orientation and sweep before installation. Scale local computations to preserve precision when needed. Keep the independent segment rank report and report joined-component rank/DOF as unavailable. This uses local analytic correction and joint residual validation with the existing worker, without adopting a general factorization or a new dependency.
4. Use the same operand and residual validation on recipe publication and Properties reopen. Route driving Length changes and changed Length Formulas through the joined solve after formula evaluation and before residual validation. A compatible length increase moves the line's End and carries an attached tangent arc while keeping both incident and tangent. Extend the existing affected-operand checks for Delete, Split, Trim, Detach and other destructive edits to cover all join records. Reject changes with ambiguous provenance and report the affected IDs. Preserve records through supported edits with proven correspondence.
5. On release, rerun the displayed proposal against current geometry, draft/source revision, click location, stage and modifier. Refuse a stale or changed target with a short diagnostic and keep the gesture. Build geometry, IDs, records and the post-acceptance gesture state as one candidate. Use the current cancellable worker job, distinguishing a draw continuation from a manual constraint command in pending state. Install and continue Line chaining or reset the Arc/Point gesture only on matching success. Reject stale or cancelled replies. Preserve the recipe, ID counters and gesture on failure. Keep the existing OK publication and an immediate path for unconstrained drawing.
