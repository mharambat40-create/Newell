## 3. Quantity and parameter contracts

Implement model-only quantities in new `newell-model/src/quantity.rs`; re-export
from `lib.rs`. Use finite `f64`, private wrapper fields and fallible constructors.
Keep existing `Length::millimetres` and `as_millimetres` call sites compatible.
No new dependency or general dimension algebra is needed.

```rust
pub struct Length(f64);                  // canonical millimetres
pub struct Angle(f64);                   // canonical radians
pub struct Scalar(f64);                  // canonical dimensionless
pub enum Quantity { Length(Length), Angle(Angle), Scalar(Scalar) }
pub enum QuantityKind { Length, Angle, Scalar }
pub enum Unit { Millimetre, Degree, Unitless }
pub enum Direction { Forward, Reverse } // separate from Quantity

Length::millimetres(value: f64) -> Result<Length, ModelError>;
Length::as_millimetres(self) -> f64;
Angle::radians(value: f64) -> Result<Angle, ModelError>;
Angle::degrees(value: f64) -> Result<Angle, ModelError>;
Angle::as_radians(self) -> f64;
Angle::as_degrees(self) -> Result<f64, ModelError>;
Scalar::new(value: f64) -> Result<Scalar, ModelError>;
Scalar::value(self) -> f64;
Quantity::kind(self) -> QuantityKind;
Quantity::parse_literal(source: &str, unit: Unit) -> Result<Quantity, ModelError>;
Quantity::value_in(self, unit: Unit) -> Result<f64, ModelError>;
Quantity::display(self, unit: Unit) -> Result<String, ModelError>;
```

Supported user units are exactly `mm`, `deg` and no unit. These are the only
units required by current fields and references. No inch/cm/m/rad input, unit
selector, implicit conversion between dimensions, percentage or Unicode degree
alias. Radians are the internal angular representation, not another UI suffix.
Conversion is degrees × PI/180 to radians and radians × 180/PI to degrees;
check both input and result for finiteness/overflow. Use standard conversion
methods with these semantics. Length and scalar conversions are identity.
Dimension mismatch is an error, even for zero.

Literal grammar at the model boundary: trim ASCII whitespace at ends; optional
leading ASCII sign; at least one digit overall; one optional decimal point;
optional `e`/`E` exponent with optional sign and at least one digit; optional
ASCII whitespace then the exact expected suffix (or suffix omitted, meaning
the supplied unit). Scalar accepts no suffix. No internal number whitespace,
commas, arithmetic, repeated suffixes, NaN/inf, or trailing junk. `5`, `.5`,
`5.` and `007.5` are legal. `mm`, empty, `.`, `1e`, `1 mm mm`, `2 deg` as length
are errors. Match the grammar before `f64` parsing. Distinguish malformed,
unsupported-unit, dimension-mismatch, nonfinite and overflow errors; detect
nonzero literals underflowing to zero as `Underflow` rather than silently zeroing.
Expose `ModelError::{InvalidLiteral(String), UnsupportedUnit(String),
DimensionMismatch, NonFiniteQuantity, QuantityOverflow, QuantityUnderflow,
NegativeMagnitude, ParameterOutOfRange}` (retain existing variants used by
unrelated callers). Constructors may support signed lengths/scalars for general
document parameters; command-field validation enforces nonnegative magnitude.
Normalize negative zero to positive zero at construction.

Change `ParameterValue::Literal(String)` to `Literal(Quantity)`; keep
`Expression(String)` exactly as an expression source. Remove `Eq` derives only
from enclosing model types that now contain f64; do not invent f64 Eq or an
epsilon-based equality relation. Preserve `PartialEq` and Clone/Copy as applicable.

```rust
ParameterValue::literal(length: Length) -> ParameterValue; // typed, no formatting
ParameterValue::evaluate(&self, parameters: &BTreeMap<String, Length>)
    -> Result<Length, ModelError>; // existing length-only compatibility API
ParameterValue::evaluate_quantity(&self, expected: QuantityKind,
    parameters: &BTreeMap<String, Length>) -> Result<Quantity, ModelError>;
```

`literal` constructs `Quantity::Length` directly. `evaluate` checks dimension;
the literal arm never goes through the legacy expression parser. The expression
arm preserves the existing small length evaluator, including named length
parameters and the existing `wall + 7.5 mm` regression. Do not expand its
grammar/functions or use it to parse numeric literals. Non-length expressions
return an explicit unsupported-expression error. Validate evaluated quantities
again for dimension, field range and magnitude. `Length::display` remains one
decimal presentation only. Canonical numeric data is the original f64; debugging
or round-trip text uses `f64::to_string()` on the canonical number with its
canonical dimension identified separately, never the rounded display string.
No serialization/persistence format is introduced.

## 5. Editing, display and precision

Keep four distinct states:

1. Active raw text + caret/selection + initial text/direction and dirty flag in
   `widgets::NumericFields`; incomplete text is allowed here only.
2. Accepted local field value in `CommandNumericInputs` (quantity, independent
   direction and optional formula source). Accepting a field is not committing
   a feature and must not increment the document revision.
3. Canonical typed quantity inside that value and the resulting model draft.
4. Rounded one-decimal view in NumericProjection/NumericView. No formatted value
   is ever read back to reconstruct an untouched accepted value.

On begin, show the one-decimal magnitude in the raw editor and record it as the
initial text. Enter/blur without a content or direction change emits nothing.
For example, accepted 1.23456789 mm displays/opens as 1.2 mm; focus, Enter,
Escape, redraw and reopen leave 1.23456789 stored. After the user changes the
magnitude to 1.3 and accepts it, the explicit edit replaces it with 1.3 mm.
Reopening is not an implicit precision reset. An edit whose final text and
direction equal the initial ones emits nothing, even after select-all/retyping;
preserve any formula too. A rejected character or caret movement is not dirty.
A direction-only change uses Direction, preserving full precision.

Do not enlarge fields to expose stored precision. Keep numeric input limits
from `widgets/numeric.rs` (8 integer digits, 7 for deg, one fractional digit).
Suffixes remain fixed, outside editable magnitude; only digits and `.` edit
the magnitude. `+`/`-` set orientation in directional fields; they are refused
in unsigned fields. No exponent or suffix entry is added to the compact editor;
the broader literal grammar is for validated model/app callers. Keep the Formula
editor's 256-character cap and current caret/key behavior.

| Event | Exact result |
|---|---|
| Enter while editing | Normalize valid text (`5`→`5.0`, `.5`→`0.5`, `5.`→`5.0`); enqueue changed accepted candidate; end edit; consume Enter so it cannot also confirm command |
| Escape while editing | Discard raw text and tentative direction; restore accepted source; consume Escape, leaving command open |
| Tab/BackTab, click another field, menu focus | Same field acceptance attempt, then existing focus/routing; unchanged text emits nothing |
| Empty or `.` on acceptance | Restore previous accepted view; no value request; log an incomplete-literal error once for that attempt; ordinary focus may leave; an OK activation on that same event is suppressed |
| Invalid character / digit cap | Refuse that character without mutation, as today; no new visual or repeated log |
| Pointer direction toggle outside edit | Emit Direction request for that field, no numeric edit; value and formula untouched |
| Direction toggle inside edit | Update tentative direction only; accept with the edit or discard with Escape; unchanged magnitude produces Direction request |
| Window focus loss | End by the same acceptance/restoration rule; never confirm command |
| Active field hidden by branch change | Resolve edit before switching branches using old active descriptor; retain accepted value; remove caret when hidden |
| App rejects candidate | Restore accepted view; log explicit error once; no partial accepted-entry replacement; suppress same-event command OK |
| Click numeric `☰` during an edit | Resolve that edit through the app before opening Formula; initialize from the resulting accepted source, including the unchanged source after rejection (§7) |

Use `crate::app::log` (stderr) for app/model validation failures, the current
confirmation-error route. Return typed errors to tests/callers. For an incomplete
local edit, carry a rejection through the request/result route rather than adding
a dialog. No approved visual validation state exists: add no red ink, marker,
status message, changed OK appearance or error overlay. No log on every redraw.

Canonical UI references remain the authority for all geometry: README §§2,
5.4/5.6/5.11 and relevant operation sections; caret window in `edit.rs` remains
unchanged. Preserve field rectangles, clipping order, suffix spaces, independent
☰ ownership, branch joins, hover and O(1) hit testing. Value/unit/caret are Text,
field frames Contour, direction toggle and ☰ Action under architecture §3.6.
No renderer change, animation, new draw call or palette change.

## 6. End-to-end command path and lifecycle

### 6.1 Input transaction ordering

In `finish_shell_input`, retain existing command-start, tree and selection
handling, adding numeric request processing before `sync_extrude_command`.
Process an outgoing field edit before a command replacement takes effect; it
may update the outgoing local panel cache but cannot address the new session.
Avoid reordering selection completions across their current owning session.
Concretely, drain outgoing numeric requests and validate their captured origin
first, then handle command-start/replacement, then existing tree/selection
intents, then a deferred Formula opening (§7) or pending numeric OK. A command-start
and its outgoing edit may share an input event; never allocate the incoming
session before resolving that edit.

For command OK, split terminal activation from terminal status publication.
The shell records a pending OK instead of immediately calling panel confirm and
`NumericFields::confirm`. Add these model-free types in UI `numeric.rs`:

```rust
pub struct NumericConfirmAttemptId(pub u64);
pub struct NumericConfirmRequest {
    pub document: TreeDocumentId,
    pub session: CommandInputSessionId,
    pub operation: ActionOperation,
    pub attempt: NumericConfirmAttemptId,
    pub through_sequence: u64,
}
```

ShellState allocates a checked, strictly increasing attempt id within the command
session on every explicit OK, including retries without any numeric change.
Exhaustion returns InteractionIdentityExhausted without creating an attempt.
`through_sequence` is only the numeric-edit barrier, never attempt identity.
The app tracks the last consumed attempt for that session separately from
`CommandNumericInputs.consumed_sequence`; reject replayed/older attempts before
preflight or model mutation. A fresh command session resets the attempt counter;
the full document/session/operation/attempt tuple remains unique.

Add `take_numeric_confirm() -> Option<NumericConfirmRequest>` on ShellState and
ShellController. Taking drains the outbound request (from both shell mirrors)
but retains a separate exact pending-attempt record for acknowledgement.
Allow at most one pending attempt. Use `finish_numeric_confirm(request,
accepted: bool) -> Result<Update, UiError>` on ShellController (ShellState returns
bool). Match every identity field, including attempt and barrier, against that
record: accepted closes/confirms exactly once; rejected retains Editing and
consumes the attempt. A mismatched, stale or already delivered acknowledgement
does nothing. This API acknowledges a resolved attempt, not another click.
Before resolution, Cancel/replacement invalidates an uncommitted attempt.

Pipeline for one input:

`key/press → raw editor → lexical acceptance → qualified NumericRequest →
app candidate parse/range validation → replace accepted numeric draft →
build ExtrudeSpec from accepted drafts + current branch state + owned selection
inputs → model validation → optional preview → project accepted views`.

For OK, resolve all edits through its sequence first. If an edit failed,
reject that pending attempt without model mutation. Otherwise build the complete
candidate spec, resolve the captured insertion anchor, and call
`DocumentSession::confirm_before` with that exact candidate **before** sending a
successful terminal acknowledgement. The existing method already performs model
insertion validation, revision-capacity preflight, cloned-controller editing and
commit. Optional earlier validation does not replace this final fallible call.
Do not confirm/close the panel or discard either command-input draft beforehand.
Keep a single helper for candidate construction to prevent preview/OK drift:

```rust
build_extrude_spec(ui: &ExtrudeValues, numeric: &CommandNumericInputs,
    selections: &CommandSelectionInputs) -> Result<ExtrudeSpec, AppError>;
```

Before the final call, mark this attempt consumed in app interaction state and
consume its one-shot latch. Record the call's outcome for acknowledgement:

- `Err`: log once, retain Editing/session/accepted drafts, and queue rejected
  acknowledgement. Document/controller/revision/notifications remain unchanged,
  including when `next_revision` fails after model insertion validation.
- `Ok(Some(feature))`: record the committed feature/cursor and queue accepted
  acknowledgement. Mark the session committed before any UI publication. Only
  this successful model outcome authorizes Extrude terminal closure.
- `Ok(None)`: no feature was committed; reject the attempt and retain its drafts.
  Never report a successful Extrude OK for this outcome.

Keep one app-owned pending terminal-delivery record containing the exact request,
accepted/rejected outcome and committed feature when present. Deliver through the
controller's clone/compose/publish path; failed acknowledgement publication leaves
