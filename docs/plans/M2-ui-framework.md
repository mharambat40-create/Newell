## 0. Preliminaries

### 0.1 Interpretation of ARCHITECTURE §3.4 ("newell-ui state MUST be a flat 1D array of cells")

The **rendered UI representation** is one flat `Vec<Cell>`. That is the only thing the renderer reads and the only thing pointer hit-testing reads.

Logical state (checkbox values, tree expansion, active command, open overlay) lives in plain Newell-owned structs. This is required by ARCHITECTURE §4.2 itself ("each window exclusively owns its active Workbench, selection state, and Feature Tree expansion state"). None of these structs is a widget tree: there are no parent/child widget nodes, no retained widget objects, no virtual DOM, no diffing. Cells are regenerated by plain functions from logical state. Tree *data* (mock feature tree) is stored as a flat pre-order `Vec` with depths, not as linked nodes.

The Challenger should test this interpretation. If the human disagrees, ARCHITECTURE §3.4 must be clarified first.

## 2. Goals

By the end of M2 `cargo run --release` shows a deterministic UI-only reference shell: MenuBar, CommandBar, NavigationPanel (Features + Elements trees), Viewport3D (clear colour + static NavCube placeholder), contextual ActionPanel (reference Extrude mock), StatusBar. It supports mouse and keyboard interaction, popup menus, two modal overlays, and resizable panes. All of it is drawn in one UI draw call over the viewport pass and is tested through logical cell-buffer snapshots.

## 3. Explicit non-goals

BrepKIT, `newell-kernel`/`newell-model` changes, real geometry, real features, Booleans, Extrude execution, formula evaluation, topology naming, geometric selection, functional NavCube or camera, display-mode changes, multi-window, event bus, submenus, keyboard shortcuts other than mnemonics/navigation, tooltips, cursor-icon changes, wide (CJK/emoji) characters, ligatures, text selection/clipboard, undo, theming UI, animated caret, logo atlas PNG loading, event-driven redraw (stays on the M1.3 bootstrap).

## 4. Architectural decisions

**D1. Crate dependencies.**
`newell-ui` → no dependencies (no `winit`, no `wgpu`). Pure and fully testable.
`newell-render` → `newell-ui` (read-only: `CellGrid`, `Cell`, `Theme`, `WidgetId`, `CellMetrics`, `UiFrame`), `wgpu`, `ab_glyph`.
`newell-app` → `newell-ui`, `newell-render`, `winit`. Translates winit events into `newell_ui::InputEvent`.
This matches ARCHITECTURE §1: View reads Controller state; Controller (`newell-ui` + `newell-app`) handles input.

**D2. Immediate-mode composition into a flat buffer.** Each recomposition clears the grid and repaints the whole shell from `UiState` with plain functions. There is no retained widget object and no diffing. At about 7.5k cells (142×53 on a 1280×800 Retina window) a full repaint costs microseconds.

**D3. Identity is semantic, not positional.** A `WidgetId` is derived from *what* a control is (e.g. "Extrude Depth field", "feature node 3 toggle"), never from where it is drawn. Progressive disclosure and pane resizing therefore never change identities, so hover and focus survive recomposition.

**D4. Three update levels.** `Redraw::{None, Uniforms, Cells, Layout}` (§10.3). Hover and pressed only touch uniforms.

**D5. One instance per cell, one draw call.** The GPU receives `cols × rows` instances of 16 bytes and draws `draw(0..6, 0..cols*rows)` once. Each instance composes background, glyph or logo slice, and hover/focus effects in the fragment shader. Overlays are part of the same buffer: they are painted last on the CPU and overwrite cells beneath (painter's order). This is how the `ui-design.md` §4 "layer order" is realised under ARCHITECTURE §3.4.

**D6. Per-window ownership.** `newell_ui::Ui` is a plain value owned by `App` (later by a per-window struct in M4). It holds its own `Theme`, `UiState`, `Interaction`, `CellGrid` and `MockDocument`. No `static`, `OnceLock`, `thread_local!` or global registry. `WidgetId`s are window-local values: two windows may use the same ids without conflict.

## 6. Proposed public interfaces / signatures

Signatures are binding in shape. The Executor may add private helpers, `Debug`/`Clone`/`Copy`/`PartialEq`/`Eq`/`Default` derives, and `#[must_use]`. Every fallible public function returns `Option` or `Result`. Nothing panics.

### 6.1 `cell.rs`

```rust
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub struct Cell {
    pub glyph: Glyph,
    pub style: StyleId,
    pub flags: CellFlags,
    pub widget: WidgetId,
}
impl Cell {
    pub const BLANK: Cell; // ' ', StyleId::Panel, CellFlags::NONE, WidgetId::NONE
    pub const fn new(ch: char, style: StyleId) -> Self;
}

#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum Glyph { Char(char), Logo(LogoPart) }

#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub struct LogoPart { pub logo: LogoId, pub size: LogoSize, pub dx: u8, pub dy: u8 }

#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum LogoSize { Major, Minor }
impl LogoSize { pub const fn cells(self) -> (u16, u16); } // Major (5,3), Minor (3,2)

#[repr(u8)]

pub enum LogoId { // exactly 16: fills a 1024² atlas of 256² slots
    Extrude, Revolve, Sweep, Loft, Sketch, Plane, Axis, Point,
    Fillet, Chamfer, Shell, LinearPattern, CircularPattern, Mirror, Measure, Section,
}

#[derive(Clone, Copy, Debug, Default, PartialEq, Eq)]
pub struct CellFlags(u8);
impl CellFlags {
    pub const NONE: Self;
    pub const HOVER: Self;     // shader may show hover/pressed/focus on this cell
    pub const LEFT_EDGE: Self; // first cell of a widget run: left-border highlight here
    pub const DISABLED: Self;  // routed but not activatable; no hover effect
    pub const SPLIT_V: Self;   // shared vertical separator: route by x-half to left/right neighbour
    pub const SPLIT_H: Self;   // shared horizontal separator: route by y-half to upper/lower neighbour
    pub const fn union(self, other: Self) -> Self;
    pub const fn contains(self, other: Self) -> bool;
}
```

### 6.3 `grid.rs`

```rust
#[derive(Clone, Debug, PartialEq, Eq)]
pub struct CellGrid { cols: u16, rows: u16, cells: Vec<Cell>, generation: u64 }
impl CellGrid {
    pub fn new(cols: u16, rows: u16) -> Self;              // zero dims allowed: empty
    pub fn cols(&self) -> u16;
    pub fn rows(&self) -> u16;
    pub fn len(&self) -> usize;
    pub fn is_empty(&self) -> bool;
    pub fn index(&self, col: u16, row: u16) -> Option<usize>;      // row * cols + col
    pub fn position(&self, index: usize) -> Option<(u16, u16)>;
    pub fn get(&self, col: u16, row: u16) -> Option<&Cell>;
    pub fn get_mut(&mut self, col: u16, row: u16) -> Option<&mut Cell>;
    pub fn cells(&self) -> &[Cell];
    pub fn clear(&mut self, fill: Cell);                   // generation += 1 (wrapping)
    pub fn resize(&mut self, cols: u16, rows: u16, fill: Cell); // generation += 1
    pub fn generation(&self) -> u64;
    pub fn to_text(&self) -> String; // rows joined by '\n'; Glyph::Logo → '▣'
}
```

Invariant: every recomposition starts with `clear()`, so `generation` changes exactly when cell content may have changed. The renderer compares generations instead of receiving a "dirty" bool, so a skipped frame can never lose an upload.

### 6.5 `metrics.rs`

```rust
pub const BASE_UNIT: u32 = 3;   // 9×15 px cells at scale factor 1.0
pub const MAX_UNIT: u32 = 64;

#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub struct CellMetrics { width: NonZeroU32, height: NonZeroU32 }
impl CellMetrics {
    pub fn from_unit(unit: NonZeroU32) -> Self;        // 3u × 5u, unit clamped to MAX_UNIT
    pub fn for_scale_factor(scale: f64) -> Self;       // unit = round(BASE_UNIT * scale) clamped to [1, MAX_UNIT]; non-finite → BASE_UNIT
    pub fn width(self) -> NonZeroU32;
    pub fn height(self) -> NonZeroU32;
    pub fn grid_dims(self, width_px: u32, height_px: u32) -> (u16, u16); // floor division, saturating to u16::MAX
}
```

`NonZeroU32` makes division by zero unrepresentable (same idea as M1.3 `FramePacer`). 3:5 is exact by construction.

### 6.6 `geom.rs`, `paint.rs`, `borders.rs`

```rust

impl Rect {

    pub fn split_right(self, w: u16) -> (Rect, Rect);

    pub const fn widget(self, id: WidgetId) -> Self; // also sets HOVER
    pub const fn flags(self, flags: CellFlags) -> Self;

#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum Line { Light, Double }

pub struct Painter<'g> { grid: &'g mut CellGrid, clip: Rect }
impl<'g> Painter<'g> {
    pub fn new(grid: &'g mut CellGrid) -> Self;             // clip = whole grid
    pub fn with_clip(&mut self, rect: Rect) -> Painter<'_>; // clip ∩ rect (reborrow)
    pub fn clip(&self) -> Rect;
    pub fn put(&mut self, col: u16, row: u16, cell: Cell) -> bool;   // false if clipped
    pub fn fill(&mut self, rect: Rect, brush: Brush);                // spaces
    pub fn text(&mut self, col: u16, row: u16, text: &str, brush: Brush) -> u16; // one char = one cell; returns cells written; first cell gets LEFT_EDGE if brush has a widget
    pub fn text_fit(&mut self, col: u16, row: u16, max: u16, text: &str, brush: Brush) -> u16; // truncates with '…'
    pub fn hline(&mut self, col: u16, row: u16, width: u16, ch: char, brush: Brush);
    pub fn frame(&mut self, rect: Rect, line: Line, style: StyleId); // standalone box (overlays), no junction merging
    pub fn logo(&mut self, col: u16, row: u16, logo: LogoId, size: LogoSize, brush: Brush); // writes size.cells() LogoPart cells with dx/dy
    pub fn set_widget(&mut self, rect: Rect, id: WidgetId, flags: CellFlags); // retags existing cells
}

/// Pane borders. Each cell holds 4 arms × 2 bits (0 none, 1 light, 2 double) = one u8.
pub struct BorderMask { cols: u16, rows: u16, arms: Vec<u8> }
impl BorderMask {
    pub fn new(cols: u16, rows: u16) -> Self;
    pub fn add_rect(&mut self, rect: Rect, line: Line);
    pub fn add_hline(&mut self, col: u16, row: u16, width: u16, line: Line);
    pub fn add_vline(&mut self, col: u16, row: u16, height: u16, line: Line);
    pub fn resolve_into(&self, painter: &mut Painter<'_>, style: StyleId); // writes ═║╔╗╚╝╠╣╦╩╬ (and light set)
}
pub fn junction_char(arms: u8) -> Option<char>; // pure table; mixed light/double resolves to the double glyph
```

Coordinates are absolute grid coordinates everywhere. All writes outside the clip or grid are silently ignored. `text` treats every `char` as one cell; wide characters are a non-goal.

## 8. Cell and WidgetId design

### 8.1 What `Cell` contains, and why

| Field | Needed for | Size |
|-------|------------|------|
| `glyph: Glyph` (`Char(char)` or `Logo(LogoPart)`) | rendering | 8 B |
| `style: StyleId` | rendering (resolved to colours at upload) | 1 B |
| `flags: CellFlags` | hover eligibility, left-edge highlight, disabled, split routing | 1 B |
| `widget: WidgetId` | O(1) routing; shader comparison with hovered/pressed/focused | 4 B |

Total with padding: **16 bytes**, guarded by a test (`size_of::<Cell>() <= 16`). `Cell` holds no strings, no logical values (checked/expanded/selected are already expressed by the glyph and style that `compose()` chose), and no transient state (hover/pressed/focus are uniforms). It is `Copy`.

### 8.2 Styling: indexed `StyleId`, not embedded colours

| Option | CPU per cell | GPU per cell | Theme change | Snapshot readability |
|--------|--------------|--------------|--------------|----------------------|
| Embedded fg+bg RGBA in `Cell` | 24 B | 16 B | full recompose | colour numbers |
| **`StyleId` (u8) into `Theme`** | **16 B** | **16 B** (resolved at encode) | re-encode only | **semantic names** |
| Palette uniform, index on GPU | 16 B | 8 B | uniform write | semantic |

Chosen: `StyleId` on the CPU, resolved to RGBA during `encode_instances`. The CPU cell stays semantic and small. The GPU instance carries real colours so the shader needs no palette array (no uniform array stride rules). A full upload is 7.5k × 16 B = 120 KB, only when the generation changes. The third option saves 60 KB per upload at the cost of a palette uniform and indirection in the shader. That is not worth it at this scale.

### 8.3 Default theme (`Theme::dark()`, sRGB hex)

| StyleId | fg | bg | Use |
|---------|----|----|-----|
| Panel | C8CCD4 | 1E2127 | panel text and background |
| Dim | 7A818C | 1E2127 | secondary text, NavCube |
| Border | 4B5263 | 1E2127 | pane borders |
| Accent | 61AFEF | 1E2127 | section titles, formula marker |
| Mnemonic | E5C07B | 282C34 | mnemonic letter in bars |
| Selected | FFFFFF | 3E4451 | selected segment, tree row, menu highlight, caret |
| Disabled | 5C6370 | inherits panel/overlay bg per call site (two entries if needed) | disabled controls |
| Viewport | C8CCD4 | 00000000 (transparent) | viewport interior: 3D pass shows through |
| Bar | C8CCD4 | 282C34 | MenuBar, CommandBar, StatusBar |

If `Disabled` needs two backgrounds, add `DisabledOverlay`. Exact colours are placeholders, like M1.3's `CLEAR_COLOR`.

### 8.4 `WidgetId` strategy

`WidgetId(u32) = scope << 16 | local`, `0 = NONE`. Locals are `u16`, so `new` cannot overflow or alias.

| Scope | `local` encoding | Example |
|-------|------------------|---------|
| MenuTitle | `AppMenu as u16` | File title |
| MenuItem | `menu << 8 \| entry_index` | File ▸ Quit |
| CommandTab | `CommandTab as u16` | Create tab |
| CommandItem | `tab << 8 \| entry_index` | Create ▸ Extrude |
| FeatureTree / ElementTree | `node << 1 \| is_toggle` | node 3 row, node 3 `[+]` |
| ActionPanel | `field << 8 \| part` | Depth field; End `◀` (part 1) / value (2) / `▶` (3); Operation option 2 |
| Overlay | `kind << 12 \| index` (kind: 1 list item, 2 OK, 3 Cancel, 4 formula text, 5 about OK) | SelectionPanel item 4 |
| Splitter | `Splitter as u16` | NavigationPanel splitter |

Properties:
* **O(1) hit-testing:** the id is in the cell. No lookup table.
* **Repeated cells:** every cell of a control carries the same id. Only the first carries `LEFT_EDGE`.
* **Dynamic ActionPanel:** ids come from `ExtrudeField`, not from row numbers, so disclosure never renumbers anything.
* **Menus and overlays:** `Overlay::owns(id)` is a `match` on scope (`Menu` popups own `MenuItem`/`CommandItem`; modals own `Overlay`). That is the focus trap. No rectangle tests.
* **Multiple windows:** ids are plain values local to one `Ui`. Nothing global.
* **No GPU or model dependence:** ids are built from UI enums and mock indices. When a real model arrives, tree locals will map from model-owned stable keys through a per-window table. The 32k node limit (`node << 1` in `u16`) is acceptable for M2 and is listed in §20.

## 9. Layout architecture

### 9.1 Primitives

Only `Rect` with `split_*`, `inset`, `intersect`, `centered_in`, plus `Painter` clipping. No constraint solver, no flex, no percentages beyond the one Features/Elements ratio.

### 9.2 Shell grid (rows)

```
row 0           MenuBar        " File  Edit  View  Help                    Newell "
row 1           CommandBar     " Workbench │ Sketch │ Create │ … │ Inspect      Part Design "
row 2           ╔══════════╦═══════════════════════╦══════════════╗
rows 3..R-3     ║ NavPanel ║ Viewport3D            ║ ActionPanel  ║
row R-2         ╚══════════╩═══════════════════════╩══════════════╝
row R-1         StatusBar      " Ready                       Part Design │ mm │ 100×30 "
```

The NavigationPanel interior holds a "Features" header and tree, a `╠═══╣` divider row, then an "Elements" header and tree. Features get `(h - 1) * 3 / 5` rows (integer).

The NavCube placeholder is painted inside the viewport at top-right, inset by 1 cell, `Dim` style, `WidgetId::NONE`:

```
┌───────┐
│  TOP  │
│ FRONT │
└───────┘
```

The ActionPanel is visible iff `state.command.is_some()` (contextual).

### 9.3 Width allocation (`shell_layout`)

```
if cols < MIN_COLS || rows < MIN_ROWS → TooSmall ("Window too small" centred)
want_nav = show_nav; want_act = show_action
loop {
    seps  = 2 (outer) + want_nav + want_act
    avail = cols - seps - VIEWPORT_MIN          (saturating)
    nav   = want_nav ? max(sizes.navigation, NAV_MIN) : 0
    act   = want_act ? max(sizes.action, ACTION_MIN) : 0
    excess = (nav + act).saturating_sub(avail)
    shrink nav toward NAV_MIN by up to excess; then act toward ACTION_MIN by the remainder
    if nav + act <= avail → done
    if want_nav { want_nav = false; continue }
    if want_act { want_act = false; continue }
    done (viewport only)
}
viewport width = cols - seps - nav - act
```

The requested sizes in `PaneSizes` are never overwritten, so widening the window restores them. Shrink order: navigation first (the ActionPanel content needs its width more), then action, then hide navigation, then hide action.

### 9.4 Borders

`compose()` builds one `BorderMask` from the layout (outer rect, both separators as vertical double lines spanning rows 2..R-1, the nav divider as a horizontal double line), then resolves it. `╦ ╩ ╠ ╣` appear automatically where lines meet. Overlay frames use `Painter::frame`, painted later, and never merge with pane borders (popups: `Line::Light`; modals: `Line::Double`).

### 9.5 Splitters

The separator column (rows 3..R-3) is retagged with `WidgetId::new(Scope::Splitter, …)` and `HOVER` after borders are resolved. Splitter cells are drag handles, **not** `SPLIT_V` cells. Dragging: `drag_width()` converts the pointer column into a requested width (navigation: `pointer_col - 1`; action: `cols - 2 - pointer_col`), stored in `PaneSizes` after clamping to `[min, cols]`. The result is `Redraw::Layout` only if the effective layout changes.

### 9.6 Dynamic ActionPanel height

The panel body scrolls (`ExtrudeUi::scroll`). The footer (OK/Cancel, 2 rows with a separator) is pinned to the bottom of the panel. Scroll changes with the mouse wheel over the panel and automatically when focus moves to a row outside the visible range (`panel_rows`).

## 10. Event / hit-testing flow

### 10.1 Flow

```
winit WindowEvent                               (newell-app/app.rs)
  → input::map_*  → newell_ui::InputEvent       (newell-app/input.rs)
  → Ui::handle(event) -> Response               (newell-ui/controller.rs)
       PointerMoved: store pointer; hit_test(grid, metrics, x, y)
                     trap: if modal overlay and !overlay.owns(id) → id = NONE
                     drag active → drag_width → maybe Layout
                     hovered = id; changed → Uniforms
       PointerButton down: hit = hit_test(pointer); trap; splitter → start drag;
                     non-modal popup + click outside popup and not a title → close popup (consume) → Cells
                     else pressed = id, focus = id if focusable → Uniforms/Cells
       PointerButton up:  if hit id == pressed && !disabled → activate(id, Click | DoubleClick) ; pressed = NONE
       Key: overlay first (trap), then focused widget, then global (Tab, F10, Alt+mnemonic, Escape)
       activate(id, how): match id.scope() → mutate UiState → Cells / Layout ; may return UiAction::Quit
  → App: if action == Quit → exit; else window.request_redraw() if redraw != None
RedrawRequested
  → frame = ui.frame()              (recomposes iff dirty >= Cells; layout recomputed inside compose)
  → renderer.render(&frame)         (re-encodes instances iff generation or dims changed; writes 64 B globals every frame)
```

`App` holds `ui` and `renderer` as separate fields, so `renderer.render(&self.ui.frame())`-style borrowing is disjoint. If the borrow checker objects to borrowing through `self`, destructure `let Self { ui, renderer, .. } = self;` first.

### 10.2 `hit_test` algorithm

```
if !(x.is_finite() && y.is_finite()) || x < 0 || y < 0 → None
px = x as u32; py = y as u32                       // float→int `as` saturates; no UB
col = px / w; row = py / h                         // w, h: NonZeroU32
if col >= cols || row >= rows → None               // includes the right/bottom remainder strip
i = row * cols + col; c = cells[i]
if c.flags ∋ SPLIT_V:
    n = if px % w < w / 2 { col > 0 ⇒ i - 1 } else { col + 1 < cols ⇒ i + 1 }
    return Hit from cells[n] (or widget NONE if no neighbour)
if c.flags ∋ SPLIT_H:
    n = if py % h < h / 2 { row > 0 ⇒ i - cols } else { row + 1 < rows ⇒ i + cols }
    ...
Hit { col, row, widget: c.widget, disabled: c.flags ∋ DISABLED }
```

Left half is `[0, w/2)`. For odd widths (w = 9) the left half is 4 px and the right half 5 px. Routing is one hop: a neighbour that is itself a separator is not followed.

**SPLIT_V users:** `│` between segmented options, `│` between CommandBar tabs. **SPLIT_H users:** separator rows inside popup menus (upper half → item above, lower half → item below), which extends item hitboxes to their visual borders (backlog M2.6).

### 10.3 What each change costs

| Change | Level | CPU work | GPU upload |
|--------|-------|----------|------------|
| Hover enters/leaves a widget | Uniforms | none | 64 B globals |
| Press / release without activation | Uniforms | none | 64 B |
| Pointer move within same widget | None | none | none (globals still written each frame; 64 B) |
| Window resize, same cols/rows | None | surface reconfigure (existing) | 64 B |
| Focus change (Tab, click) | Cells | recompose (caret, auto-scroll) | instances |
| Checkbox, segment, cyclic step, tree toggle, text edit | Cells | recompose | instances |
| Menu/overlay open/close/highlight, list scroll | Cells | recompose | instances |
| Splitter drag changing effective width, nav panel toggle, ActionPanel open/close | Layout | recompose (layout inside) | instances (+ grow buffer if needed) |
| Window resize changing cols/rows | Layout | grid resize + recompose | instances (+ grow) |
| Scale factor change | Layout | metrics, grid resize, recompose | glyph atlas rebuild + instances |

`Layout` and `Cells` both recompose fully; `Layout` additionally resizes the grid. Keeping them distinct documents intent and lets tests assert that, e.g., a checkbox never triggers `Layout`.

### 10.4 Interaction rules

* `hovered` is whatever `hit_test` returns, after the trap. The shader decides visibility from `HOVER`/`DISABLED`.
* Activation happens on release over the same widget that received the press. Moving off while pressed shows `Normal`; releasing outside does nothing.
* Double click: a second primary press on the same widget within `DOUBLE_CLICK_MS` of the previous release yields `Activation::DoubleClick`. Only the cyclic value cell uses it (steps forward, as `ui-design.md` §2 says). A single click on the value only focuses.
* `PointerLeft` sets `hovered = NONE` and cancels `pressed` (not drag; drag ends on release).
* Disabled cells route their id (so clicks do not fall through) but never activate or show hover.

## 11. Rendering pipeline

### 11.1 Passes per frame

1. **Viewport pass** (existing): `LoadOp::Clear(CLEAR_COLOR)`, no draws. M3 adds 3D content here.
2. **UI pass**: `LoadOp::Load`, `StoreOp::Store`, one pipeline, one bind group, one instance vertex buffer, **one `draw(0..6, 0..cols*rows)`**. Skipped if the grid is empty.

Both passes are in one command encoder and one submit.

### 11.2 Instance format (16 bytes, little-endian u32 × 4, step mode Instance)

| Word | Bits | Meaning |
|------|------|---------|
| w0 | 31 | `1` = logo cell |
| w0 | 0–15 | glyph atlas slot (text) |
| w0 | 0–7 / 8–10 / 11–12 / 13 | logo: slot (`LogoId as u8`) / dx / dy / size (0 Minor, 1 Major) |
| w0 | 24 / 25 / 26 | HOVER / LEFT_EDGE / DISABLED |
| w1 | — | fg RGBA8 (`r \| g<<8 \| b<<16 \| a<<24`) |
| w2 | — | bg RGBA8 |
| w3 | — | `WidgetId::raw()` |

`SPLIT_*` flags are CPU-only and not encoded. Instance `i` is cell `i`; the vertex shader derives `col = i % cols`, `row = i / cols`. Six vertices come from `vertex_index`; there is no vertex buffer for geometry.

### 11.3 Globals uniform (64 bytes, all `u32`)

| Offset | Field |
|--------|-------|
| 0, 4 | cols, rows |
| 8, 12 | cell_w, cell_h (px) |
| 16, 20 | target_w, target_h (surface px) |
| 24, 28, 32 | hovered, pressed, focused (`WidgetId::raw`) |
| 36 | glyph_columns (atlas slots per row) |
| 40 | srgb_target (1 if the surface format is sRGB) |
| 44 | accent_px = max(1, cell_w / 9) |
| 48–63 | padding |

### 11.4 Bind group 0 (the M2.4 ADR records this)

| Binding | Resource |
|---------|----------|
| 0 | Globals uniform buffer |
| 1 | Glyph atlas, `R8Unorm`, read with `textureLoad` (slot size equals cell size, so no sampler) |
| 2 | Logo atlas, `Rgba8UnormSrgb`, 1024², full mip chain |
| 3 | Linear sampler (min/mag/mip linear, clamp to edge) |

Two textures in one bind group, one pipeline, one draw. This keeps ARCHITECTURE §3.4 and ADR 0002 D6.

### 11.5 Fragment shader rules

* Local pixel `l = floor(position.xy) - cell_origin` (cell origin passed `flat`).
* **Text:** `cov = textureLoad(glyph, slot_origin + l).r`. Output `bg` blended with `fg × cov` (straight alpha, standard alpha blending in the pipeline). Transparent `bg` + space ⇒ alpha 0 ⇒ the viewport pass shows through.
* **Logo (ARCHITECTURE §3.3 Scale-to-Fit):** block size `B = (cols_b × cell_w, rows_b × cell_h)` from the size bit; pixel in block `p = (dx × cell_w, dy × cell_h) + l + 0.5`; `side = min(B.x, B.y)`; `off = (B - side) / 2`; `uv = (p - off) / side`; outside `[0,1]²` ⇒ transparent; else sample slot `(slot % 4, slot / 4) × 0.25 + uv × 0.25` with `textureSampleLevel(lod = log2(256 / side))`. The CPU only supplies integers `dx, dy`; all sub-pixel maths is in the shader.
* **Hover** (`widget == hovered && HOVER && !DISABLED`): text fg → white `#FFFFFF`; if `LEFT_EDGE` and `l.x < accent_px` paint accent `#61AFEF`; logos `rgb × 1.4` (clamped).
* **Pressed** (`widget == pressed && HOVER`): bg × 0.8.
* **Focus** (`widget == focused && LEFT_EDGE`): left `accent_px` columns in `#E5C07B` (hover accent wins if both).
* **Colour space:** colours are sRGB bytes. If `srgb_target == 1`, convert fg/bg to linear with the exact sRGB transfer function before blending. Logo texels are linearised by the texture format.
* No time input. No animation.

### 11.6 Upload policy

`UiPipeline` stores `uploaded_generation` and `uploaded_dims`. If either differs from the frame, it runs `encode_instances` into a reused `Vec<u8>` and `queue.write_buffer`. If the needed size exceeds capacity, the buffer is recreated with `max(needed, 2 × capacity)`. The glyph atlas is rebuilt only in `set_cell_metrics`. Slot indices depend only on charset order, not on metrics, so instances stay valid across a metrics change.

### 11.7 ADR (created by the Executor in M2.4)

`docs/adr/0003-ui-overlay-binding.md`, status **Proposed**, content: §11.2–11.4 decisions; alternatives considered (texture array: rejected, glyph atlas is R8 and logos are RGBA with different sizes; combined RGBA atlas: rejected, 4× glyph memory and POT rule mixing); consequence: one bind group, one pipeline, one draw. Uses `docs/adr/0000-template.md`.

### 12.1 Crate: `ab_glyph 0.2.32`

| | ab_glyph 0.2.32 | fontdue 0.9.4 | fontdue 0.9.3 |
|-|-----------------|---------------|---------------|
| Builds on 1.85 | **yes (verified 2026-10-13, `cargo +1.85.0 check`)** | **no** (uses `integer_sign_cast`, stable in 1.87) | yes |
| Declared MSRV | none | none | none |
| Licence | Apache-2.0 (allowed) | MIT OR Apache-2.0 OR Zlib | same |
| New crates in lock | ab_glyph, ab_glyph_rasterizer, owned_ttf_parser (ttf-parser already present) | fontdue (+ hashbrown 0.15/ttf-parser already present) | same |
| API needed | `FontRef::try_from_slice`, `glyph_id`, `h_advance_unscaled`, `height_unscaled`, `ascent/descent`, `outline_glyph().draw()` | `rasterize`, `horizontal_line_metrics` | same |

fontdue would need an exact `=0.9.3` pin to stay on 1.85, and its latest release already left the MSRV. ab_glyph works at its latest version, has a small API that covers the need, and adds three small crates. Declare `ab_glyph = "0.2.32"` (caret, like `wgpu = "26.0.1"`); `Cargo.lock` and the MSRV CI job guard it.

### 12.2 Font file

`include_bytes!` from `assets/FiraCode-Regular.ttf` (path relative to `ui/glyph_atlas.rs`). Compile-time embedding avoids working-directory and packaging problems with `cargo run`. Parse errors map to `RenderError::Font`. The file must be committed together with its licence (`assets/OFL.txt`). See §21 blocker 1.

### 12.3 Glyph sizing at a forced 3:5 cell

* Font scale: `px = cell_w × height_unscaled / h_advance_unscaled(' ')`, so the monospace advance fills `cell_w` exactly. (In ab_glyph, `PxScale` is the ascent−descent height.)
* Vertical placement ("ink-box centring"): measure the union of outline bounds of `[A-Za-z0-9]` at that scale: `top` (max height above baseline) and `bottom` (max depth below). If `top + bottom ≤ cell_h`, `baseline = round((cell_h - top - bottom) / 2) + top`. Otherwise `baseline = cell_h - bottom` (descender-anchored), and the `alnum_not_clipped` test will fail and report it.
* Each glyph is rasterised into its own `cell_w × cell_h` slot at `(0, baseline)` using the outline's `px_bounds`; coverage outside the slot is dropped. Accents above capitals may clip; labels are ASCII.
* Slot order: `REQUIRED_GLYPHS` order. `columns = 32`. Atlas `width = 32 × cell_w`, `height = ceil(n / 32) × cell_h`. At `MAX_UNIT` this is 6144 × 1600, below the default 8192 limit; `AtlasTooLarge` covers devices with lower limits.
* A required non-procedural glyph with `glyph_id == 0` is reported by the `required_charset_present` test. At runtime a missing glyph renders the `?` slot.

### 12.4 Procedural box drawing

Fira Code's box glyphs are designed for its natural ~1:2 cell, not 3:5, so they would not join. The 22 box characters in `REQUIRED_GLYPHS` are drawn by `rasterize_box`:

* `t = max(1, w / 9)`; `xc = (w - t) / 2`, `yc = (h - t) / 2`; double offsets `d = 2t`: `L = xc - d`, `R = xc + d`, `T = yc - d`, `B = yc + d`. A segment "at x from y0..y1" is a `t`-wide stroke; ranges include the far stroke's thickness.
* Light: a stroke from the centre square to each present edge (`─ │ ┌ ┐ └ ┘ ├ ┤ ┬ ┴ ┼`).
* Double, exact segments:

| Char | Segments |
|------|----------|
| `═` | H at T 0..w; H at B 0..w |
| `║` | V at L 0..h; V at R 0..h |
| `╔` | H at T L..w; V at L T..h; H at B R..w; V at R B..h |
| `╗` | H at T 0..R; V at R T..h; H at B 0..L; V at L B..h |
| `╚` | V at L 0..B; H at B L..w; V at R 0..T; H at T R..w |
| `╝` | V at R 0..B; H at B 0..R; V at L 0..T; H at T 0..L |
| `╦` | H at T 0..w; H at B 0..L and R..w; V at L B..h; V at R B..h |
| `╩` | H at B 0..w; H at T 0..L and R..w; V at L 0..T; V at R 0..T |
| `╠` | V at L 0..h; V at R 0..T and B..h; H at T R..w; H at B R..w |
| `╣` | V at R 0..h; V at L 0..T and B..h; H at T 0..L; H at B 0..L |
| `╬` | V at L 0..T, B..h; V at R 0..T, B..h; H at T 0..L, R..w; H at B 0..L, R..w |

Because every glyph uses the same `L, R, T, B`, neighbouring cells join exactly. A snapshot at 9×15 and 18×30 pins the output for human review.

### 12.5 Placeholder logo atlas

`placeholder_logo_atlas()`: 1024×1024 RGBA8, 4×4 slots of 256². Each slot: 8 px fully transparent padding on every side; the 240×240 art box is a filled square of a distinct deterministic hue (`hue = slot × 360 / 16`) with a 16 px darker inner frame, alpha 255. Mip chain to 1×1 by 2×2 box filter. It meets every ARCHITECTURE §3.2 rule, needs no decoder dependency, and is replaced by the real PNG in a later milestone (§20).

## 14. ActionPanel strategy

### 14.1 Framework

There is no generic form engine. A command's UI is:
1. a plain state struct (`ExtrudeUi`),
2. `visible_fields()`: a pure function giving the disclosure,
3. `paint(&PanelBuilder)`: plain Rust `if`s that emit typed rows in a fixed order,
4. `activate(field, part, how)`: a `match` that mutates the struct and returns an `ExtrudeEvent`.

`ActiveCommand` is a one-variant enum now. Later commands add variants. No trait objects, no registry. The controller maps `ExtrudeEvent::OpenSelection` → `Overlay::Selection`, `OpenFormula(f)` → `Overlay::Formula`, `Commit`/`Cancel` → close panel and set the status text.

## 15. Overlay strategy

* **One overlay at a time:** `UiState::overlay: Option<Overlay>`. The reference UI never needs nesting (FormulaEditor and SelectionPanel both open from the ActionPanel, menus from bars). An overlay stack is deferred (§20).
* **Painted last** in `compose()`, overwriting cells below with opaque `Overlay` style. Same buffer, same draw call. No extra pass.
* **Placement:** popups via `popup_rect` under their title (menubar: row 1; command bar: row 2); modals via `modal_rect` centred over the viewport rect (`ui-design.md` §2).
* **Popup menus:** `Line::Light` frame. App menu entries are one row each; separators are routed `─` rows (`├───┤`). Command menu entries are two rows: Minor logo (3×2) at the left, label on row 1, dim hint on row 2. Entries without a logo leave the 3×2 area blank. Disabled entries in `Disabled` style. Checked entries show `✓`. Popups are **non-modal**: a press outside closes the popup and is consumed, except on another title of the same bar, which switches menus.
* **Modals:** `Line::Double` frame, title in the top border, OK/Cancel area via `confirm_row`. Focus trap: `focus_order` contains only overlay ids; pointer hits outside are mapped to NONE (no hover, no activation). Escape = Cancel.

## 21. Genuine unresolved blockers

1. **Font asset missing (blocks M2.3 and everything visual after it).** `assets/FiraCode-Regular.ttf` does not exist. The human must add it with `assets/OFL.txt`. Fira Code is licensed under SIL OFL 1.1. OFL allows bundling with software of any licence (the font itself must stay under OFL and not be sold on its own). That is compatible with distributing Newell under AGPL-3.0-or-later. However, this is a third-party licence outside `deny.toml`, so under ARCHITECTURE §6 the human must confirm it. M2.1, M2.2, and M2.5–M2.12 logic do not need the font and can proceed first.

2. **Logo atlas (non-blocking, needs confirmation).** No atlas PNG exists. The plan uses a generated placeholder that follows every §3.2 rule (§12.5). Confirm, or provide the real atlas and approve a PNG decoder crate.

3. **Segmented selectors vs `ui-design.md` §2 (non-blocking, needs confirmation).** `ui-design.md` says selectors with ≤ 3 options use `◀ {Value} ▶`. The brief asks for segmented selectors for Solid/Surface and New/Add/Remove. ARCHITECTURE is silent, so the brief is followed. Confirm, and update `ui-design.md` §2 if this is the intended rule.

4. **§0.1 interpretation of ARCHITECTURE §3.4 (non-blocking, needs confirmation).** The plan reads "flat 1D array of cells" as the rendered UI representation, with logical state in plain structs (no widget tree). If the human reads §3.4 more strictly, ARCHITECTURE.md must be clarified before M2.6.

No other blockers. All other choices have defaults documented above.
